## 1. 왜 사람이 봐야 하는가

인용 검증(`citation.py`)은 **발췌가 원문에 있는지**만 본다. 발췌는 맞는데 조건 요약이 원문에 없는 내용을 말하는 경우가 남는다. 조건 요약은 20자 이내로 줄인 문장이라 원문과 문자열이 일치하지 않아서, 문자열 대조로는 잡을 수 없다.

숫자(금액·비율·나이·기간)는 `grounding.py` 가 자동으로 잡는다. **뜻이 어긋난 요약은 사람만 잡을 수 있다.**

## 2. 점검 방법

1. 정책별로 **원문에 있는 조건 목록**을 3절 표에 미리 적어 둔다. 공고 원문(`raw_text`)에 문장으로 있는 조건만 적는다.
2. 본선 당일 화면(카드·상세 판정표·각주·조건부 문장)에 나온 조건을 하나씩 3절 목록과 대조한다.
3. **목록에 없는 조건이 화면에 나오면 1건으로 센다.** 같은 조건이 여러 화면에 반복되면 1건이다.
4. 같은 뜻이지만 범위가 달라진 것도 1건이다. 예: 원문 "휴학생 제외"를 "재학생만 신청 가능"으로 넓혀 말한 경우.

세지 않는 것: 규칙 엔진이 판정한 조건(나이·지역·신분·소득·마감), 조건 요약이 비어 있는 미확인 조건, 판정 실패 자리표시.

## 4. 자동 검출 먼저 돌리기

사람 눈으로 볼 목록을 줄인다. 숫자와 "근거 없는 요약"은 기계가 정확하다.

```bash
# 사용법과 한계 확인
python3 -m ai.judgment.grounding
```

```python
from ai.judgment.grounding import check_conditions

report = check_conditions(result["conditions"], policy["raw_text"])
print(report.summary())          # 지표 슬라이드에 그대로 옮긴다
for issue in report.issues:
    print(issue.kind, issue.token, issue.condition_name, issue.detail)
```

| 검출 종류 | 무엇 | 사람이 할 일 |
| --- | --- | --- |
| `ungrounded_number` | 조건 요약의 숫자가 원문에 없음 | 원문을 열어 확인하고 6절에 1건으로 옮긴다 |
| `name_without_excerpt` | 근거 없이 조건 요약만 화면에 나감 | 화면에 실제로 나갔는지 확인하고 옮긴다 |

자동 검출이 놓치는 것: 한 자리 수(요약을 다듬다 생기는 잡음이라 건너뛴다), 전각 숫자(없는 문제를 잡는 쪽으로 기울어진다 — 원문을 보고 걸러낸다), **뜻이 어긋난 요약**.
