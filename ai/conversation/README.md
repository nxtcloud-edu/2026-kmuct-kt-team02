## 1. 목표

사용자가 편하게 말해도 프로필과 의도를 정확히 읽고, 판정이 갈리는 것만 묻고, 결론 먼저·근거는 각주로 답하는 대화.

여기서 실패하면 제품이 그냥 검색 필터가 된다. 대화형이 기존 서비스와의 유일한 차별점이므로, 데모에서 관객이 "오" 하는 순간은 5번(후속 질문으로 카드가 바뀜)과 6번(한마디로 프로필이 바뀜)에서 나온다.

## 2. 담당 범위

메시지 해석, 후속 질문 선택과 문장, 답변 작성, 각주 매핑, 관련 질문 칩, 대화 평가.

| AI가 하는 것 | 코드가 하는 것 |
| --- | --- |
| 자연어에서 관심 분야·생활 사건·프로필 변경 추출 | 어떤 정보를 물을지 **선택** |
| 답변 설명 작성 | 판정 상태 확정 |
| (P1) 질문 문장을 맥락에 맞게 다듬기 | D-day와 날짜 계산 |
| — | 각주 번호 부여 |
| — | 이미 물었거나 건너뛴 항목 기록 |

경계가 이렇게 그어진 이유는 하나다. **모델이 잘하는 일(문장 이해와 생성)과 못 믿을 일(셈, 날짜, 일관된 판정)을 섞지 않는다.**

## 3. 메시지 해석

### 뽑아낼 것

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 의도 | `find_policy`, `policy_question`, `compare`, `result_only`, `out_of_scope`, `smalltalk` | 하나만 |
| 프로필 변경 | 항목 이름, 값, 시점(`current` 또는 `planned`) | 여러 개 가능 |
| 추가 항목 답변 | 항목 이름과 값 | 묻지 않았어도 말했으면 반영 |
| 관심 분야 | 추가할 분야, 제외할 분야 | |
| 언급된 정책 | 정책 번호 | 특정 정책 질문일 때 |

항목 이름과 허용 값은 `../../docs/01-glossary-profile.md` 2~3장이 유일한 기준이다. **표에 없는 항목을 만들지 않는다.**

### 해석 기준

- 확실히 말한 것만 반영한다. 추측해서 채우지 않는다.
- 미래 계획("다음 학기에 휴학해요")은 시점을 `planned`로 두고 **프로필을 바꾸지 않는다.** 대신 "휴학 후 기준으로 볼까요, 지금 기준으로 볼까요?"를 후속 질문으로 붙인다.
- 폼 값과 다르게 말하면 **대화 값**을 따른다.
- 숫자 소득("월 200 벌어요")은 구간으로 바꾸지 않는다. 개인 소득과 가구 소득 기준이 다르므로 "가구 소득 구간을 알려주시면 더 정확해요"로 연결한다.

미래 계획을 바로 반영하지 않는 이유는, 지금 신청할 수 있는 제도를 찾는 것이 목적이기 때문이다. 휴학 예정자에게 휴학생 전용 제도를 지금 신청 가능한 것처럼 보여주면 틀린 안내가 된다.

### 의도별 동작

| 의도 | 동작 |
| --- | --- |
| `find_policy` | 전체 흐름 |
| `policy_question` | 그 정책 판정 위주로 답변, 카드 하나 강조 |
| `compare` (P1) | 두 정책의 조건·혜택·마감 비교 문단 |
| `result_only` | 후속 질문 생략, 현재 결과 정리 |
| `out_of_scope` | "행정 절차나 법률 상담은 아직 도와드리기 어려워요" 한 줄 + 할 수 있는 것 안내 |
| `smalltalk` | 한 줄 응대 후 정책 찾기 유도 |

범위 밖과 잡담은 규칙 재계산과 판정을 건너뛰고 바로 종료한다. 시간 예산을 쓰지 않는다.

## 4. 후속 질문 선택

규칙 엔진이 준 미확인 항목 목록에서 고른다. 순서대로 적용한다.

1. 미확인 항목 목록을 모은다. **이미 물었거나 건너뛴 항목은 뺀다.**
2. 항목마다, 답에 따라 상태가 바뀔 수 있는 표시 중 정책 수를 센다.
3. 수가 가장 많은 항목을 고른다.
4. 같으면 더 위에 있는 정책에 영향을 주는 항목.
5. 그래도 같으면 프로필 항목 표의 순서.
6. 고를 항목이 없으면 **묻지 않는다.**

한 턴에 하나만 묻는다. `result_only` 의도를 보이면 그 세션에서는 먼저 묻지 않는다.
**선택은 코드가 하고 AI는 문장만 다듬는다.** 선택을 모델에게 맡기면 같은 상황에서 다른 질문이 나와 데모가 흔들린다.

건너뛴 항목을 다시 묻지 않는 것은 세션이 기록한다(`../../docs/03-api-contract.md` 11장). 이걸 놓치면 사용자가 "모르겠어요"라고 답한 질문을 또 받게 되고, 대화형이라는 인상이 한순간에 깨진다.

## 5. 후속 질문 문구

화면 문구로 고정한다. 이유 문구의 ○○와 n은 실제 영향받는 정책명과 수로 채운다.
**문장 자체를 AI가 새로 만들지 않는다.** P1에서만 맥락에 맞게 다듬기를 허용한다.

| 항목 | 질문 | 이유 문구 | 선택지 |
| --- | --- | --- | --- |
| `income_bracket` | 가구 소득이 어느 정도인지 아세요? | ○○ 등 n개 제도가 소득 기준으로 갈려요 | 소득 구간 5개 |
| `district` | 어느 구에 사세요? | 구에서 하는 지원이 있어요 | 자주 쓰는 구 5개 + 직접 입력 |
| `housing_type` | 지금 어떻게 지내고 계세요? | 월세 지원은 주거 형태에 따라 달라요 | 부모님 집, 월세, 전세, 기숙사 |
| `residence_period` | 서울에 산 지 얼마나 되셨어요? | 거주 기간 조건이 있는 제도가 있어요 | 6개월 미만, 6개월~1년, 1년 이상 |
| `remaining_semesters` | 졸업까지 몇 학기 남았어요? | 졸업예정자 대상 제도가 있어요 | 1학기, 2학기 이상 |
| `job_seeking_period` | 구직 활동한 지 얼마나 됐어요? | 구직 기간 조건이 있어요 | 6개월 미만, 6개월 이상 |
| `employment_insurance` | 일하면서 고용보험에 가입한 적 있어요? | 훈련 지원 조건과 관련 있어요 | 있음, 없음, 모르겠어요 |
| `other_benefit` | 지금 받고 있는 다른 청년 지원금이 있나요? | 중복으로 못 받는 제도가 있어요 | 있음, 없음 |
| `household_size` | 함께 사는 가족은 몇 명이에요? | 소득 기준이 가구원 수로 달라져요 | 1인, 2인, 3인, 4인 이상 |
| `last_gpa` | 직전 학기 성적이 공고 기준 이상인가요? | 성적 조건이 있는 장학금이 있어요 | 기준 이상, 기준 미만, 모르겠어요 |

모든 질문에 **건너뛰기와 직접 입력**을 함께 붙인다. 이유 문구를 붙이는 목적은 심문처럼 느껴지지 않게 하는 것이다. 왜 묻는지 알면 사용자가 답할 이유가 생긴다.

## 6. 답변 구성

| 순서 | 내용 | 기준 |
| --- | --- | --- |
| 1 | 요약 | 한 문장. "신청 가능성이 높은 제도 n개, 확인이 필요한 제도 n개를 찾았어요." |
| 2 | 정책별 설명 | 표시 순서대로 최대 5개, 정책당 1~2문장. 왜 맞는지 또는 무엇이 남았는지 |
| 3 | 조건 안내 | `check`가 있으면 남은 조건을 한 문장으로 묶어 |
| 4 | 마감 강조 | 마감 임박이 있으면 한 문장 |
| 5 | 고정 문구 | "최종 신청 전 공식 공고에서 다시 확인하세요" |

### 말투와 길이

해요체. 과장·감탄·이모지 없음. 요약부터 고정 문구까지 합쳐 **600자 이내.** 정책명은 데이터의 제목 그대로.

600자로 묶는 이유는 카드가 이미 정보를 담고 있기 때문이다. 답변이 길면 카드를 읽지 않고, 그러면 각주와 조건 판정표라는 우리 차별점이 묻힌다.

### 근거 규칙

- 판정·조건·금액·날짜가 든 문장에는 **반드시 각주**를 붙인다. 각주 없는 판정 문장은 출력하지 않는다.
- 각주는 규칙 엔진과 AI B가 넘긴 조건 결과의 발췌에만 연결한다. **새 발췌를 만들지 않는다.**
- 각주 번호는 서버가 부여한 값을 쓴다. 직접 번호를 매기지 않는다.
- 금액과 날짜는 데이터 필드 값만 쓴다.
- 판정 상태는 이미 확정된 값을 설명만 한다. **답변에서 상태를 새로 판단하지 않는다.**

### 형식

답변은 스키마를 강제하지 않는다. 형식 제약이 문장 품질을 떨어뜨린다는 근거가 있고, 각주 번호는 이미 코드가 부여한 값을 쓰기 때문에 강제할 이유가 없다(`../../docs/research/04-llm-api-operations.md` 1절).

### 금지 표현

대상입니다, 받을 수 있어요, 확실히, 무조건, 100%, 보장, 걱정 마세요

### 결과 없음일 때

"지금 조건으로는 맞는 제도를 찾지 못했어요." + 조건을 넓히는 방법 + 우리 데이터 범위 한 줄.

## 7. 관련 질문 칩 (P1)

| 상황 | 칩 예 |
| --- | --- |
| `check`가 있음 | 소득 기준 확인하는 방법 알려줘 |
| `unlikely`가 있음 | 조건이 안 맞는 이유가 뭐야? |
| 카드 2개 이상 | 상위 두 개 비교해줘 |
| 마감 임박 있음 | 마감 임박한 것부터 준비 순서 알려줘 |

최대 3개. 이미 물어본 것과 같은 칩은 뺀다. 일정이 밀리면 고정 문구 3개로 대체한다(`../../docs/00-overview.md` 빼는 순서 2번).

## 8. 해석 테스트 케이스

사전 준비 산출물이다. 프롬프트를 고칠 때마다 다시 돌린다.

| 입력 | 기대 해석 |
| --- | --- |
| 방학 동안 취업 준비하면서 생활비 지원 받을 수 있는 거 있어? | `find_policy`, 관심 분야 취업·생활비 |
| 저 이번 달부터 자취해요 월세로 | 주거 형태 월세, 관심 분야 주거 추가 |
| 다음 학기에 휴학할 거예요 | 상태 휴학 `planned`, 프로필 유지, 확인 질문 |
| 사실 저 졸업했어요 | 상태 졸업 후 구직으로 변경 |
| 두 번째 거랑 세 번째 거 비교해줘 | `compare`, 표시 순서로 정책 특정 |
| 그냥 결과만 보여줘 | `result_only` |
| 전입신고 어떻게 해? | `out_of_scope` |
| 부모님이랑 같이 살아요 | 주거 형태 부모님 집 |
| 월 150 벌어요 | 프로필 변경 없음, 가구 소득 안내 |
| 고마워! | `smalltalk` |

## 9. 대화 평가 케이스

| 번호 | 대화 | 통과 기준 |
| --- | --- | --- |
| C1 | P1 프로필 + 데모 첫 문장 | 요약 문장 있음, 각주 있음, 600자 이내, 금지 표현 없음 |
| C2 | C1 후 소득 질문에 "모르겠어요" | 같은 질문 다시 안 함, 다음 항목으로 |
| C3 | 저 이번 달부터 자취해요 | 프로필 변경 표시, 주거 정책 등장 |
| C4 | 다음 학기에 휴학할 거예요 | 프로필 유지, 확인 질문 |
| C5 | 결과만 보여줘 | 후속 질문 없음 |
| C6 | 전입신고 어떻게 해? | 범위 밖 안내 한 줄 |
| C7 | 결과 없는 관심 분야 | 결과 없음 안내와 넓히는 방법 |
| C8 | 모든 항목 건너뛰기 | 질문 멈춤, `check` 결과 정리 |

C2와 C8이 가장 중요하다. 이 두 개가 깨지면 후속 질문이 심문이 된다.
