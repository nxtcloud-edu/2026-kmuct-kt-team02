# 정책 데이터 (담당: 백엔드A)

> 출처: 역할별 설계서 3-1~3-3, PRD v2 11장.
> **필드 규격은 `../docs/04-data-schema.md`가 기준이다.** 필드 이름, 작성 규칙, 규칙 조건 판정 기준은 그 문서를 보고, 이 문서는 수집하는 사람이 실제로 무엇을 해야 하는지만 다룬다. 두 문서가 어긋나면 `../docs/04-data-schema.md`를 따른다.

## 1. 목표

검수된 정책 20~30건을 모은다. 서비스가 내놓는 모든 판정의 근거가 이 폴더에서 나온다. 요약하거나 다듬은 문장은 각주로 쓸 수 없으므로, 공고 원문에서 가져오는 부분은 **원문과 글자까지 같아야 한다.** 판정이 틀리는 사고는 대부분 모델이 아니라 여기서 시작된다.

## 2. 폴더 구조

| 경로 | 내용 |
| --- | --- |
| `policies/` | 정책별 문서. 사전 준비는 스프레드시트로 하고 당일 데이터 파일로 변환한다 |
| `profiles/` | 대표 프로필 P1~P5 정의. 자세한 내용은 `profiles/README.md` |
| `eval/` | 평가 기준과 채점 방법. 정답셋 자체는 커밋하지 않는다. `eval/README.md` 참고 |

## 3. 수집 분담

5명이 5~6건씩 나눠 수집한다. 형식 검토는 백엔드A가 맡는다. 같은 정책을 두 사람이 붙잡는 일을 막기 위해, **수집을 시작하기 전에 각자 맡을 정책명을 공유한다.** 수집 도중에 추가할 정책이 생기면 그때도 먼저 공유한다.

## 4. 수집 기준

| 기준 | 내용 |
| --- | --- |
| 출처 | 서울시·중앙부처·공공기관의 공식 공고 원문만 쓴다. 블로그, 커뮤니티, 뉴스 기사는 정책을 찾는 단서로만 쓰고 출처로 적지 않는다 |
| 대상 | 서울에 사는 만 19~24세 대학생·휴학생·졸업예정자·취업준비생이 받을 가능성이 있는 제도 |
| 시기 | 9/20 기준 접수 중이거나, 상시 접수이거나, 10월 중 접수가 시작되는 것 |
| 제외 | 교내 공지, 특정 기업 채용 공고, 자치구 한정 정책은 넣지 않는다. 자치구 한정은 데모 다양성용으로 2건까지만 허용한다 |

### 수집·갱신 방식

- 수동 수집과 검수를 기본으로 한다.
- 반복 확인이 필요한 공식 출처가 있거나 수동 수집만으로 일정 준수가 어려울 때만 출처별 최소 크롤링을 구현한다.
- 크롤링 결과는 검수 후보로만 취급한다. 서비스 데이터에 넣기 전에 필드 변환, 정책별 검수 체크리스트, 다른 사람의 교차 확인을 모두 거친다.
- 전국 정책 실시간 수집과 무검수 자동 반영은 하지 않는다.

## 6. 데이터 전체 조건

개별 정책이 다 맞아도 이 네 가지가 깨지면 데모가 살지 않는다. **수집 중간과 마감 직전에 두 번 확인한다.**

| 조건 | 기준 | 왜 필요한가 |
| --- | --- | --- |
| 접수 중·상시 접수 | 9/20 기준 15건 이상 | 결과 화면이 비거나 마감된 정책만 남는 상황을 막는다 |
| 소득 조건 없는 정책 | 전체의 30% 이상 | 소득을 모르는 사용자에게도 `likely`가 나오게 한다 |
| 추가 항목 조건이 있는 정책 | 5건 이상 | 후속 질문으로 판정이 바뀌는 장면을 시연한다 |
| 데모 프로필에서 `unlikely`가 나오는 정책 | 2건 이상 | 미충족 이유와 대안 정책 흐름을 시연한다 |

## 7. 작성할 때 자주 틀리는 것

| 상황 | 이렇게 한다 |
| --- | --- |
| `raw_text`를 읽기 좋게 줄이고 싶을 때 | 줄이지 않는다. 요약하면 인용 검증이 깨진다. 복사 붙여넣기만 한다 |
| 상시 접수 정책 | `apply_end`를 비운다. "예산 소진 시까지"도 마감일 없음으로 보고 비우되, 그 문장은 `raw_text`에 그대로 남긴다 |
| 공고가 나이를 출생연도로 적었을 때 | 9/20 기준 만 나이로 바꿔 넣고, 출생연도로 쓴 원문은 `raw_text`에 그대로 둔다 |
| 건강보험료 기준 등 중위소득 %가 아닌 소득 기준 | `income_max_pct`를 비우고 해당 문장을 `exceptions_text`로 옮긴다 |
| 공고가 대상을 "대학생"이라고만 썼을 때 | `statuses`에는 재학만 넣는다. 휴학 포함 여부가 불분명하면 그 문장을 `exceptions_text`로 옮긴다 |
| 추가 항목을 새로 만들고 싶을 때 | 만들지 않는다. `../docs/01-glossary-profile.md` 3장 표에 있는 항목만 쓴다 |

## 8. 검수 체크리스트

정책 한 건마다 아래를 모두 통과해야 한다.

- [ ] `source_url`을 열었을 때 공고 원문이 바로 보인다
- [ ] 마감일이 원문과 같다
- [ ] 나이, 지역, 신분, 소득 필드가 원문과 모순되지 않는다
- [ ] `raw_text`가 원문과 글자까지 같다
- [ ] `benefit`의 금액이 원문에 있다
- [ ] 필드로 옮기지 못한 조건이 `exceptions_text`에 빠짐없이 있다
- [ ] `condition_sources`의 문장이 `raw_text` 안에 그대로 있다
- [ ] 다른 사람 1명이 교차 확인했다

## 9. 당일 변환

10:30~11:30에 스프레드시트를 데이터 파일로 변환한다. 변환이 끝나면 필수 필드 누락과 날짜 형식을 한 번 훑는다. 이 시간대를 넘기면 이후 일정이 밀리므로, 변환 대상은 전날까지 확정해 둔다.

## 10. 완료 기준
