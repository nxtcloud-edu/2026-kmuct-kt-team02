# 대표 프로필 (담당: 백엔드A)

> 출처: 역할별 설계서 3-3, PRD v2 11장. 프로필 항목의 허용 값은 `../../docs/01-glossary-profile.md`가 기준이다.

## 1. 용도

대표 프로필 5개는 추천 정확도와 판정 일치율을 채점하는 기준이다. 같은 프로필로 데모에서 보여줄 경로가 실제로 동작하는지도 함께 확인한다. 즉 지표용이면서 리허설용이다.

## 2. 대표 프로필

| 번호 | 프로필 | 확인하려는 것 |
| --- | --- | --- |
| P1 | 만 23세, 서울, 재학, 관심 분야 취업·생활비, 소득 모름 | 데모 기본 경로. 소득 기준이 있는 정책에서 `check`와 조건부 문장이 나오는지 |
| P2 | 만 22세, 서울(자치구 선택), 휴학, 관심 분야 주거·생활비, 소득 50~100%, 월세 | 주거 형태 추가 항목이 물어지고, 답한 뒤 `likely`로 바뀌는지 |
| P3 | 만 24세, 서울, 졸업예정, 관심 분야 취업·훈련, 소득 100~150% | 신분 변화가 판정에 반영되는지, 마감 임박 정렬이 맞는지 |
| P4 | 만 23세, 서울, 재학, 관심 분야 생활비, 소득 150% 초과 | 소득 미충족으로 `unlikely`가 나오고 미충족 이유와 대안이 제시되는지 |
| P5 | 만 19세, 서울, 재학, 관심 분야 전체 | 나이 하한 미달로 `unmet`이 나오는지. 만 19세는 `age_min` 21 정책에서 `unmet`, 19 정책에서 `met` |

> P5는 원래 "만 21세, 서울 외"로 서울 한정 정책이 `unlikely`가 되는지 보는 케이스였다.
> `region`이 `seoul` 고정으로 확정돼(`../../docs/01-glossary-profile.md` 2장) 서울 외 프로필을 만들 수 없으므로 나이 하한 경계로 교체했다.
> 자치구 불일치는 자치구 한정 정책이 데이터에 없어 검증할 수 없고, 단위 테스트로 덮는다.

## 3. 값을 적는 방법

프로필 값은 `../../docs/01-glossary-profile.md` 2~3장의 허용 값으로 적는다. 표에 없는 값을 새로 만들지 않는다. 예를 들어 소득을 모르는 경우는 `unknown`으로, 주거 형태는 `monthly_rent`처럼 정해진 값으로 적는다.

`region`은 **`seoul` 고정**이다. 클라이언트가 전송하지 않고 서버가 채우므로 프로필 정의에도 `seoul`만 쓴다.
`district`는 선택 입력이고, 비우면 자치구 한정 정책이 **미확인**으로 남는다.

값 정의 파일은 `profiles.json`이다. `profile` 객체 안에는 Profile 계약 필드만 넣는다.
`server/schemas.py`의 `ContractModel`이 `extra="forbid"`이므로 `id`나 메모를 섞으면 검증이 실패한다. 그래서 `id`와 검증 목표는 형제 키로 두었다.

## 4. P1과 데모 프로필

P1은 데모 프로필과 같은 값이다. P1에서 판정이 흔들리면 데모가 그대로 흔들린다는 뜻이므로 가장 먼저 확인한다. 데모 순서는 `../../docs/06-demo-and-metrics.md` 1~2장을 참고한다.

## 5. 이 폴더에 두는 것

이 폴더에는 프로필 5개의 값 정의만 둔다. **기대 판정 결과(정답셋)는 여기에 두지 않는다.** 채점 방법은 `../eval/README.md`에 있다.
