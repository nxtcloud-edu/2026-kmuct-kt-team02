# 02. 기능 요구사항 (EARS)

> 출처: PRD v2 9장. **본선 당일 09:00 KIRO Spec 요구사항 입력의 본문.**
> `docs/01-glossary-profile.md`와 자기 역할 폴더 README를 함께 넣는다.

## FR01 온보딩 폼

THE SYSTEM SHALL 서울 거주를 고정 전제로 나이, 현재 상태, 관심 분야를 필수로 받고 자치구와 가구 소득 구간을 선택으로 받는다.
`region`은 클라이언트에서 입력받지 않고 서버 내부 Profile에서 `seoul`로 고정한다.
소득에는 "잘 모르겠어요"를 둔다.
IF 필수 항목이 비어 있으면 THE SYSTEM SHALL 시작 버튼을 비활성화한다.

**인수 기준**: 필수 3개 미입력 시 시작 불가. `region` 입력 UI와 요청 필드는 없고 응답 Profile은 항상 `region=seoul`이다. 소득 기본값은 `unknown`. 나이 15~39 밖은 입력 거부.

## FR02 자연어 해석과 프로필 갱신

WHEN 사용자가 메시지를 보내면 THE SYSTEM SHALL 관심 분야, 생활 사건, 프로필 변경 정보를 추출한다.
IF 추출 값이 기존 프로필과 다르면 THE SYSTEM SHALL 대화 값을 적용하고 변경 사실을 화면에 표시하며
결과를 다시 계산한다.

**인수 기준**: "저 이번 달부터 자취해요" → `housing_type=monthly_rent`, 관심 분야에 `housing` 추가,
프로필 바에 변경 강조 2초, 주거 정책이 결과에 등장.

## FR03 후보 검색

THE SYSTEM SHALL 공식 출처가 등록되고 마감되지 않은 정책 중 관심 분야가 맞는 것만 후보로 삼고,
상위 3~5개를 반환한다.

**인수 기준**: `data_status=closed` 정책은 후보에서 제외. 관심 분야 교집합이 없으면 제외.

## FR04 답 먼저

WHEN 폼을 제출하거나 첫 메시지를 보내면 THE SYSTEM SHALL 후속 질문보다 먼저 1차 결과 카드를 표시한다.

**인수 기준**: 폼 제출 → 카드 표시 2초 이내. 규칙 엔진 결과만으로 카드가 뜬다. AI 응답을 기다리지 않는다.

## FR05 후속 질문

WHEN 상위 후보 중 하나 이상의 판정이 미확인 정보 하나로 바뀔 수 있으면 THE SYSTEM SHALL 그 정보를 묻는
질문을 한 번에 하나, 선택지·직접 입력·건너뛰기와 함께 제시한다.
IF 그런 정보가 없으면 THE SYSTEM SHALL 질문하지 않는다.
WHEN 사용자가 건너뛰면 THE SYSTEM SHALL 해당 조건을 미확인으로 유지한다.

**인수 기준**: 건너뛴 항목을 다시 묻지 않는다. 판정을 바꾸지 않는 정보는 묻지 않는다.
"결과만 보여줘" 의도면 그 세션에서 먼저 묻지 않는다.

## FR06 신청 가능성 상태

THE SYSTEM SHALL 각 정책을 `likely`, `check`, `unlikely` 중 하나로 표시하고, 문구와 아이콘을 함께 보여준다.

**인수 기준**: 색만으로 구분하는 곳이 없다. 상태 결정은 `docs/01-glossary-profile.md` 4장 규칙을 따른다.

## FR07 조건별 근거와 각주

THE SYSTEM SHALL 조건마다 충족·미충족·미확인을 표시하고 공고 원문 발췌를 각주로 연결한다.
IF 발췌문이 원문에 존재하지 않으면 THE SYSTEM SHALL 그 조건 설명을 출력하지 않고 미확인으로 처리한다.

**인수 기준**: 각주를 누르면 발췌·기관·확인일·원문 링크가 뜬다. 인용 검증 실패 발췌는 화면에 나가지 않는다.
각주 없는 판정 문장이 0건.

## FR08 조건부 결과

IF 미확인 조건이 있고 미충족 조건이 없으면 THE SYSTEM SHALL "○○라면 신청 가능" 형태의 조건부 문장을
카드에 표시한다.

**인수 기준**: 소득 `unknown` 프로필에서 카드가 "확인이 필요해요" + 조건부 문장으로 보인다.
조건부 문장은 고정 형식에 값만 채운다 (`ai/judgment/README.md` 참고).

## FR09 마감 표시와 정렬

THE SYSTEM SHALL `docs/01-glossary-profile.md` 5~6장의 마감 표시 규칙과 정렬 규칙을 따른다.
D-day는 코드로 계산한다.

**인수 기준**: 마감 지난 정책이 기본 결과에 없다. 마감 임박이 같은 상태 안에서 위에 온다.
확인일 14일 초과 정책에 재확인 필요 표시가 붙는다.

## FR10 정책 상세

WHEN 카드를 선택하면 THE SYSTEM SHALL 조건별 판정표, 혜택, 마감, 서류, 신청 단계, 담당 기관, 공식 링크,
최종 확인일을 한 화면에 표시한다.

**인수 기준**: 조건 판정표 순서는 미충족 → 미확인 → 충족. 각 조건에 각주 버튼이 있다.

## FR11 신청 체크리스트

WHEN 상세 화면을 열면 THE SYSTEM SHALL 서류와 신청 단계를 체크 가능한 항목으로 보여주고,
마지막 항목에 공식 신청 페이지 링크를 둔다.

**인수 기준**: 서류 항목이 먼저, 신청 단계가 다음. 체크 상태는 세션 동안만 유지.

## FR12 출처와 확인일

THE SYSTEM SHALL 모든 카드와 상세에 공식 출처와 최종 확인일을 표시한다.
IF 둘 중 하나라도 없으면 THE SYSTEM SHALL 그 정책을 결과에서 제외한다.

**인수 기준**: 출력된 정책 중 `source_url`과 `checked_at`이 둘 다 있는 비율 100%.

## FR13 대안과 결과 없음

IF 정책이 `unlikely`이면 THE SYSTEM SHALL 미충족 조건과 같은 분야의 대안 정책을 제시한다.
IF 후보가 없으면 THE SYSTEM SHALL 데이터 범위, 조건을 넓히는 방법, 온통청년 링크를 보여준다.

**인수 기준**: 소득 초과로 `unlikely`인 정책을 열면 미충족 이유와 같은 분야 대안이 보인다.

## FR14 진행 상태 표시

WHILE AI 응답을 생성하는 동안 THE SYSTEM SHALL "정책 찾는 중 → 조건 확인 중 → 정리 중" 단계를 표시하고
답변을 스트리밍한다.

**인수 기준**: 답변 첫 문장이 3초 이내 시작. 전체 20초 상한. 단계 표시가 순서대로 갱신된다.

## FR15 민감정보 차단

IF 입력에 주민등록번호나 계좌번호 형식이 있으면 THE SYSTEM SHALL AI에 보내기 전에 가리고
입력하지 말라는 안내를 표시한다.

**인수 기준**: 가린 값이 AI 요청과 로그 어디에도 남지 않는다. 입력창 아래 안내 문구가 뜬다.
