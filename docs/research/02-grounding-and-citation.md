# 근거성과 인용 검증

> 조사 목적: 공고 원문을 컨텍스트에 직접 넣고 "조건 판정 + 원문 발췌"를 각주로 붙이는 우리 구조의 가드레일 설계 근거를 확보한다.
> 조사일 2026-09-20. 출처는 인라인 링크로 표기했다.

## 한 줄 결론

- **인용 검증은 선택이 아니라 필수다.** 인용을 붙이게 하는 것만으로는 근거성이 보장되지 않는다는 것이 이 분야의 출발점이다.
- **문자열 대조를 느슨하게 풀지 않는다.** 통과율이 낮게 나오면 그건 검증기의 문제가 아니라 모델이 원문을 바꿔 쓴 것이다.
- **후보 문서를 많이 넣을수록 불리하다.** 입력이 길어지고 중간에 묻히면 성능이 떨어진다. 상위 몇 건으로 제한한다.
- **형식 강제는 안전하지만 공짜가 아니다.** 추론 품질이 떨어질 수 있으니 판정과 문장 생성을 분리해 둔 현재 구조를 유지한다.
- **애매하면 미확인.** 잘못된 단정의 비용이 미확인의 비용보다 훨씬 크다.

## 1. 인용을 붙이는 것과 근거가 있는 것은 다르다

| 발견 | 내용 | 자료 | 연도 |
| --- | --- | --- | --- |
| 모델은 유용한 답을 내면서도 환각을 일으키고, 신뢰할 출처 참조가 빠져 신뢰도가 떨어진다는 문제의식에서 인용 생성 연구가 출발했다 | 문제 정의 | [세밀한 보상으로 인용 생성 학습](https://arxiv.org/html/2402.04315v1) | 2024 |
| 인용 품질을 자동으로 재는 최초의 벤치마크가 제안됨. 유창성·정확성·인용 품질 세 축으로 평가하고 사람 판단과 상관이 높음 | ALCE | [인용이 달린 텍스트 생성 (ALCE)](https://arxiv.org/abs/2305.14627) | 2023 |
| 문장 단위 인용만으로는 부족하고, 문장 안 위치별 인용까지 봐야 한다는 후속 지적. 인용 재현율·정밀도와 인용 위치 분산을 지표로 씀 | ALiiCE | [위치 기반 세밀 인용 평가](https://arxiv.org/html/2406.13375) | 2024 |
| 근거에 밀착한 인용을 학습시키면 인용 품질이 크게 올라간다 | 기준선 대비 평균 14.21% 개선 | [근거 밀착 인용 학습 (FRONT)](http://arxiv.org/abs/2408.04568v1) | 2024 |

**우리 제품에 주는 함의**: 인용 품질은 "모델에게 각주를 달라고 지시하면 해결되는 문제"가 아니라 별도로 측정하고 걸러내야 하는 대상이다. 우리는 학습을 할 수 없으므로 **출력 후 검증**으로 대응한다. 우리 지표 중 "인용 검증 통과율 100%"와 "근거 없는 조건 0건"이 이 축을 담당한다.

## 2. 문자열 대조 검증의 한계와 우리 선택

우리 방식은 발췌를 공백 정규화한 뒤 원문 안에 그대로 있는지 확인하는 것이다. 연구 쪽의 자동 평가는 보통 함의 판정 모델을 쓰거나 LLM 심사자를 쓴다.

| 접근 | 장점 | 한계 |
| --- | --- | --- |
| 문자열 대조 (우리 방식) | 결정적이고 빠르다. 판단 주체가 모델이 아니라 로직이라 설명이 쉽다 | 모델이 문장을 미세하게 바꿔 쓰거나 줄임표를 넣거나 표를 풀어 쓰면 통과하지 못한다 |
| 함의 판정 모델 | 의미가 같으면 통과시킨다 | 모델을 하나 더 두는 비용. 판정 근거를 사용자에게 설명하기 어렵다 |
| LLM 심사자 | 유연하다 | 검증 대상과 같은 종류의 실패를 공유한다. [심사자 성능을 벤치마크하려는 시도](https://arxiv.org/html/2607.08700v1)가 나온 것 자체가 신뢰가 자동이 아니라는 뜻이다 |

**우리 제품에 주는 함의**: 우리 상황에서는 문자열 대조가 맞다. 이유는 세 가지다.

1. 우리가 보여주는 것은 요약이 아니라 **원문 발췌 그 자체**다. 의미가 같은 다른 문장은 애초에 필요하지 않다.
2. 하루 안에 만들고 발표해야 한다. 판정 주체를 로직으로 두면 "왜 이 조건이 사라졌나"를 즉시 설명할 수 있다.
3. 실패 방향이 안전하다. 통과하지 못하면 미확인으로 강등되므로 잘못된 단정이 나가지 않는다.

**대신 이렇게 보완한다**: 통과율이 낮게 나오면 검증을 느슨하게 푸는 게 아니라 **발췌 요구를 더 좁힌다.** 원문에서 연속된 한 구간을 그대로, 10~150자로, 조건당 하나만 가져오게 한다. 표를 원문에 그대로 넣지 말고 `raw_text` 단계에서 한 줄씩 풀어 두는 것도 같은 대비다(`docs/04-data-schema.md`).

## 3. 형식 강제의 효과와 대가

| 발견 | 내용 | 자료 | 연도 |
| --- | --- | --- | --- |
| 형식 제약을 걸면 추론 능력이 유의하게 떨어진다. 제약이 엄격할수록 저하가 크다 | 경고 | [형식 제약의 영향 연구](https://arxiv.org/abs/2408.02442) | 2024 |
| 제약 디코딩은 스키마 준수를 보장하는 방향으로 표준화됐지만, 실제 효과에 대한 이해는 부족하다 | 평가 필요 | [구조화 출력 생성 평가와 JSONSchemaBench](https://arxiv.org/html/2501.10868v2) | 2025 |
| 목록이나 복합 객체를 내놓아야 하는 과제에서 난도가 올라간다 | 우리 구조가 여기에 해당 | [JSON 응답 형식 연구](https://arxiv.org/html/2408.11061v1) | 2024 |
| 최근에는 저하의 원인이 형식 자체보다 모델 용량이라는 재해석도 제시됨 | 반론 | [구조화 추론 실패 재검토](https://arxiv.org/pdf/2606.09410) | 2026 |

**우리 제품에 주는 함의**: 우리는 형식 강제를 유지한다. 근거 없는 조건이 화면에 나가는 위험이 추론 품질 손실보다 크다. 다만 위 연구를 고려해 **판정과 문장 생성을 분리한 현재 설계를 유지한다**.

| 호출 | 형식 | 이유 |
| --- | --- | --- |
| 예외 조건 판정 (AI B) | 강하게 강제 | 결과를 코드가 받아 처리한다. 형식이 깨지면 쓸 수 없다 |
| 답변 작성 (AI A) | 강제하지 않음. 자연어 스트리밍 | 형식 제약이 문장 품질을 떨어뜨린다. 각주 번호는 이미 코드가 부여한 값을 쓴다 |

조건 판정 항목을 단순하게 유지하는 것도 대비다. 조건당 항목이 네 개뿐이고 중첩이 얕다.

## 4. 애매함을 미확인으로 남기는 설계

우리 판정은 세 갈래(`met`, `unmet`, `unknown`)이고, 애매하면 `unknown`으로 둔다. 이건 선택적 예측과 회피(abstention)의 실무적 형태다.

| 근거 | 내용 |
| --- | --- |
| 1절 | 인용을 붙여도 근거성이 보장되지 않는다. 확신을 표시할 수단이 부족하다 |
| 3절 | 형식 강제 아래에서 추론이 약해질 수 있다. 약한 추론으로 단정하면 피해가 크다 |
| 제품 쪽 비대칭 | `unmet` 오판은 사용자가 받을 수 있는 제도를 잃게 한다. `unknown` 오판은 질문 하나가 더 늘어날 뿐이다 |

**우리 제품에 주는 함의**: `unmet`은 프로필에 명시된 값으로 분명할 때만 쓴다. 조금이라도 애매하면 `unknown`. 그리고 `unknown`이 결과를 비게 만들지 않도록 조건부 문장(FR08)으로 메운다. 이 두 장치가 짝이다. 하나만 있으면 제품이 무용해진다.

## 5. 긴 문맥과 후보 문서 수

| 발견 | 내용 | 자료 | 연도 |
| --- | --- | --- | --- |
| 관련 정보가 입력의 앞이나 뒤에 있을 때 성능이 가장 높고, 중간에 있으면 크게 떨어진다 | 위치 효과 | [장문 컨텍스트 사용 방식 (Lost in the Middle)](https://arxiv.org/html/2307.03172v1) · [학술지 게재본](https://direct.mit.edu/tacl/article/doi/10.1162/tacl_a_00638/119630) | 2023~2024 |
| 입력이 길어질수록 성능이 떨어진다. 장문 전용 모델도 예외가 아니다 | 길이 효과 | 같은 연구 | 2023~2024 |
| 이 현상은 이후 연구에서도 계속 확인된다 | 재현 | [정보 검색 요구에서 비롯된 성질로 보는 해석](https://arxiv.org/html/2510.10276v1) | 2025 |

**우리 제품에 주는 함의**: 벡터 검색을 쓰지 않는 결정은 유지한다(정책이 20~30건이라 규칙 필터가 더 정확하다). 다만 **한 번의 호출에 여러 정책 원문을 몰아넣지 않는다.** 이미 설계가 정책 하나씩 판정하고 후보를 동시에 처리하는 방식이라 이 위험을 피한다. 호출 한도가 빡빡해서 묶어야 한다면 상위 3건까지만 묶고, 지시문은 앞과 끝에 두고 원문을 가운데에 둔다.

## 우리 설계에 반영할 것

| 발견 | 반영할 규칙 | 담당 |
| --- | --- | --- |
| 인용은 붙이는 것만으로 보장되지 않는다 | 모든 발췌를 로직으로 원문과 대조. 실패 시 `unknown`으로 강등하고 화면에서 제거. 제거 건수 기록 | AI B, 백엔드B |
| 문자열 대조는 바꿔 쓴 문장을 잡지 못한다 | 검증을 풀지 않고 발췌 요구를 좁힌다. 연속 구간, 10~150자, 조건당 하나 | AI B |
| 표를 그대로 넣으면 대조가 깨진다 | `raw_text`에서 표를 한 줄씩 풀어 쓴다 | 백엔드A |
| 형식 강제는 추론을 약화시킬 수 있다 | 판정은 형식 강제, 답변 문장은 강제하지 않음. 조건 항목을 얕게 유지 | AI B, AI A |
| 애매함의 비대칭 | `unmet`은 명시된 값으로 분명할 때만. 나머지는 `unknown` + 조건부 문장 | AI B |
| 긴 입력과 중간 묻힘 | 정책당 개별 판정. 묶어야 하면 3건까지, 지시문은 앞과 끝 | AI B, 백엔드B |
| 규칙과 AI가 겹칠 때 | 명시 조건은 규칙 엔진만 판정. AI는 문장형 예외 조건만 | 백엔드A, AI B |

## 반영하지 않기로 한 것

| 항목 | 왜 |
| --- | --- |
| 함의 판정 모델이나 LLM 심사자로 인용 검증 | 모델을 하나 더 두는 비용과 시간. 우리는 원문 발췌 그대로를 보여주므로 의미 일치 판정이 필요하지 않다 |
| 인용 정밀도·재현율 정량 측정 | 4시간 안에 측정 파이프라인을 세울 수 없다. 대신 "근거 없는 조건 0건"을 수동 점검으로 확인한다 |
| 위치별 세밀 인용 (문장 안 여러 지점) | 조건당 각주 하나로 충분하다. 복잡도만 늘어난다 |
| 인용 품질 개선을 위한 학습·미세조정 | 범위 밖 |
| 벡터 검색 도입 | 정책 20~30건에서는 규칙 필터가 더 정확하고 빠르다 |
