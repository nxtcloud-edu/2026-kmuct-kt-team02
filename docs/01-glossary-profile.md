# 01. 용어와 프로필 규격

> 출처: 역할별 설계서 1장 (공통). **모든 역할이 이 값을 그대로 쓴다.** 10:30 확정 후 변경 금지.
> 바꿔야 하면 백엔드A가 표를 고치고 전원에게 공지한다. 표에 없는 항목은 대화에서 묻지 않는다.

## 1. 용어

| 용어 | 뜻 |
| --- | --- |
| 세션 | 한 사용자의 한 번 사용. 서버 메모리에만 있고 30분 비활성 또는 새로고침 시 폐기 |
| 프로필 | 폼과 대화로 모은 사용자 정보. 기본 항목 5개 + 추가 항목 |
| 후보 | 관심 분야가 맞고 마감되지 않은 정책 |
| 판정 상태 | 정책 단위 결과. `likely`, `check`, `unlikely` |
| 조건 결과 | 조건 단위 결과. `met`(충족), `unmet`(미충족), `unknown`(미확인) |
| 판정 주체 | `rule`(규칙 엔진) 또는 `ai`(예외 조건 판정) |
| 조건부 문장 | check 상태일 때 남은 조건을 "○○라면 신청 가능해요"로 풀어쓴 문장 |
| 각주 | 판정 문장에 붙는 번호. 누르면 공고 원문 발췌, 출처, 확인일이 뜸 |
| 발췌 | 공고 원문에서 그대로 가져온 연속된 문장 일부 |
| 확인일 | 팀이 공고 원문을 마지막으로 확인한 날짜 (`checked_at`) |
| D-day | 한국 시간 오늘부터 마감일까지 남은 일수. 코드만 계산 |

## 2. 기본 프로필 항목 (온보딩 폼)

| 항목 | 필드명 | 필수 | 허용 값 | 비고 |
| --- | --- | --- | --- | --- |
| 나이 | `age` | 필수 | 만 나이 정수 15~39 | 범위 밖은 폼에서 막음 |
| 거주 지역 | `region` | 입력 안 함 | `seoul` 고정 | 서버 내부 Profile과 응답에만 포함. 클라이언트가 값을 선택하거나 전송하지 않음 |
| 자치구 | `district` | 선택 | 서울 25개 자치구명 또는 `null` |
| 현재 상태 | `status` | 필수 | `enrolled`(재학), `on_leave`(휴학), `final_semester`(졸업예정), `job_seeking`(졸업 후 구직), `employed`(재직) | 하나만 |
| 관심 분야 | `categories` | 필수 | `scholarship`(장학·교육), `living`(생활비), `job`(취업·훈련), `culture`(교통·통신·문화), `housing`(주거), `all`(전체) | 복수 선택. `all` 선택 시 나머지 해제 |
| 가구 소득 | `income_bracket` | 선택 | `under_50`, `50_100`, `100_150`, `over_150`, `unknown` | 기본값 `unknown` |

### 소득 구간 의미

| 값 | 뜻 | 하한 % | 상한 % |
| --- | --- | --- | --- |
| `under_50` | 기준 중위소득 50% 이하 | 0 | 50 |
| `50_100` | 50~100% | 50 | 100 |
| `100_150` | 100~150% | 100 | 150 |
| `over_150` | 150% 초과 | 150 | 무한 |
| `unknown` | 잘 모르겠어요 | — | — |

### 자치구 목록 (25개)

강남구, 강동구, 강북구, 강서구, 관악구, 광진구, 구로구, 금천구, 노원구, 도봉구, 동대문구, 동작구,
마포구, 서대문구, 서초구, 성동구, 성북구, 송파구, 양천구, 영등포구, 용산구, 은평구, 종로구, 중구, 중랑구

## 3. 추가 프로필 항목 (대화로 물음)

| 항목 | 필드명 | 허용 값 |
| --- | --- | --- |
| 주거 형태 | `housing_type` | `parents`(부모님 집), `monthly_rent`(월세), `jeonse`(전세), `dormitory`(기숙사), `other`(기타) |
| 서울 거주 기간 | `residence_period` | `under_6m`, `6m_1y`, `over_1y` |
| 남은 학기 | `remaining_semesters` | `one`, `two_plus` |
| 구직 기간 | `job_seeking_period` | `under_6m`, `over_6m` |
| 고용보험 가입 이력 | `employment_insurance` | `yes`, `no`, `unknown` |
| 다른 지원 수혜 중 | `other_benefit` | `yes`, `no` |
| 가구원 수 | `household_size` | `1`, `2`, `3`, `4_plus` |
| 직전 학기 성적 | `last_gpa` | `above`(기준 이상), `below`(기준 미만), `unknown`(모름) |

- 모든 항목은 건너뛸 수 있고, 건너뛴 항목은 **미확인**으로 남는다.
- 건너뛴 항목은 세션에 기록해 **같은 질문을 다시 하지 않는다**.
- 미래 계획("다음 학기에 휴학해요")은 시점을 `planned`로 두고 프로필을 바꾸지 않는다. 확인 질문을 붙인다.

## 4. 판정 상태 결정 규칙

| 조건 결과 조합 | 판정 상태 | 화면 문구 | 아이콘 |
| --- | --- | --- | --- |
| 규칙 조건 또는 AI 조건 중 `unmet`이 1개 이상 | `unlikely` | 어려울 수 있어요 | ✕ |
| `unmet` 없음, `unknown` 1개 이상 | `check` | 확인이 필요해요 | ? |
| 모든 조건 `met` | `likely` | 신청 가능성이 높아요 | ✓ |
| AI 판정 실패·시간 초과 | 예외 조건 전체를 `unknown`으로 두고 위 규칙 적용 | | |

- **규칙 조건과 AI 조건이 같은 내용을 다르게 판정하면 규칙 조건을 따른다.**
- 상태 문구는 **코드**가 붙인다. AI가 상태를 새로 판단하지 않는다.
- 색만으로 구분하지 않고 문구와 아이콘을 항상 함께 쓴다.
- 화면 문구는 팀 외부 3명 확인 후 확정 (프론트).

## 5. 마감 표시 규칙

| 경우 | 배지 | 기본 결과 노출 | `data_status` |
| --- | --- | --- | --- |
| 마감일이 오늘 | 오늘 마감 | 노출 | `verified` |
| 마감까지 1~7일 | 마감 임박 D-n | 노출, 같은 상태 안에서 상단 | `verified` |
| 마감까지 8일 이상 | D-n | 노출 | `verified` |
| 마감일 없음 | 상시 접수 | 노출, 같은 상태 안에서 하단 | `verified` |
| 시작일이 오늘 이후 | 접수 예정 (M.D 시작) | 노출 | `upcoming` |
| 마감일 지남 | 표시 안 함 | **제외** | `closed` |
| 확인일로부터 14일 초과 | 기존 배지 + 재확인 필요 | 노출 | `recheck` |

모든 날짜 계산은 한국 시간 기준. D-day는 코드가 계산하고 AI는 날짜를 계산하지 않는다.

## 6. 정렬 규칙

같은 상태 안에서 다음 순서로 정렬한다.

| 순서 | 기준 |
| --- | --- |
| 1 | 판정 상태: `likely` → `check` → `unlikely` |
| 2 | 마감 7일 이내(마감 임박) 먼저 |
| 3 | 마감일 빠른 순. 상시 접수는 뒤, 접수 예정은 그 뒤 |
| 4 | 관심 분야 일치 수 많은 순. 최근 대화에서 언급된 분야 우선 |
| 5 | `id` 순 (동점 처리) |

관심 분야와 무관한 정책은 후보에서 뺀다.

## 7. 후보 선정과 표시 개수

1. 후보: 관심 분야가 하나 이상 겹치고(`all` 선택 시 모두), `data_status`가 `closed`가 아닌 정책
2. 판정 상태를 매긴다
3. 기본 표시: `likely`와 `check` 중 정렬 상위 **5개**
4. 접힌 영역: `unlikely` 중 정렬 상위 **3개**
5. `likely`와 `check`가 0개면 결과 없음 흐름

## 8. 후속 질문 규칙

- 고정 개수 제한은 두지 않는다.
- 상위 후보 중 **하나 이상의 판정 상태를 바꾸는 정보만** 묻는다.
- 여러 개면 가장 많은 후보의 판정에 영향을 주는 것부터 묻는다. **선택은 코드, 문장 다듬기는 AI**.
- 한 턴에 질문은 하나. 선택지 버튼 + 직접 입력 + 건너뛰기를 함께 준다.
- 판정을 바꾸는 미확인 정보가 없으면 더 묻지 않는다.
- 질문마다 "이걸 알면 ○○ 제도 판정이 확정돼요"처럼 이유를 한 줄 붙인다.

## 9. 답변 형식 원칙

- 결론 먼저, 근거는 각주로. 첫 문장에서 몇 개가 가능하고 몇 개가 확인이 필요한지 말한다.
- 판정 관련 문장에는 반드시 원문 각주를 단다. **각주 없는 판정 문장은 출력하지 않는다.**
- "대상입니다" 같은 단정 대신 "신청 가능성이 높아요"처럼 가능성으로 말한다.
- 답변 끝에 "최종 신청 전 공식 공고에서 다시 확인하세요"를 고정 문구로 둔다.
