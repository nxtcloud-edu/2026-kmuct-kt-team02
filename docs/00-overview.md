# 00. 제품 개요

> 출처: PRD v2 1~5장, 8장, 14장, 19장, 20장

## 한 문장

서울 대학생·취업준비생이 기본 정보를 입력하고 자기 상황을 말하면, AI가 공식 공고를 근거로 받을 수 있는
지원제도를 바로 보여주고, 판정에 필요한 것만 되물으며, 신청까지 해야 할 일을 정리해 주는 대화형 서비스.

**발표용 한 줄**: 청년 지원제도를 위한 Perplexity. 모든 판정 문장에 공고 원문 각주가 달린다.

## 사용자

| 구분 | 대상 | 필요 |
| --- | --- | --- |
| 1차 | 서울 거주 만 19~24세 대학생 | 놓치고 있는 제도와 신청 가능성을 빨리 알고 싶음 |
| 2차 | 휴학생, 졸업예정자, 취업준비생 | 신분이 바뀔 때 맞는 제도를 놓치지 않고 싶음 |

만 25~34세는 설문 근거가 없어 MVP 대상에서 제외한다.

**JTBD**: 지원이 필요하거나 생활이 바뀌었을 때, 내 상황을 한 번 말하는 것만으로 지금 신청할 수 있는 제도를 찾고,
내가 해당되는지 근거와 함께 확인하고, 마감 전에 무엇을 준비해야 하는지 알고 싶다.

## 해결하는 문제

지원제도 정보는 여러 기관에 흩어져 있고, 공고문은 조건과 예외가 긴 문장에 섞여 있다.
학생들은 제도를 늦게 알고, 자기가 대상인지 판단하지 못하고, 마감과 서류 준비에서 신청을 멈춘다.
기존 서비스는 제도를 목록으로 보여주는 데는 강하지만, 개인 상황을 듣고 모르는 부분을 되묻고 근거를 대며
다음 행동까지 이어주지는 못한다.

| 단계 | 현재 행동 | 불편 | 제품 대응 |
| --- | --- | --- | --- |
| 발견 | 필요할 때 여러 사이트와 SNS를 뒤짐 | 늦게 알거나 마감을 놓침 | 입력 즉시 1차 결과 |
| 판단 | 나이·거주지·재학·소득 조건을 직접 대조 | 대상인지 확신하지 못함 | 조건별 판정 + 원문 각주 |
| 준비 | 서류와 순서를 다시 찾아 정리 | 복잡해서 중단 | 서류·단계 체크리스트 |
| 신뢰 | 게시물이 최신인지 따로 확인 | 오래된 정보나 근거 없는 AI 답변을 믿지 못함 | 출처 + 최종 확인일 |

## 기존 서비스와의 차이

| 항목 | 온통청년 | 정부24 혜택알리미 | 복지로 | 우리 |
| --- | --- | --- | --- | --- |
| 입력 방식 | 조건 필터·검색 | 본인 인증 기반 | 조건 선택·모의계산 | 짧은 폼 + 자연어 대화 |
| 모르는 정보 처리 | 사용자가 직접 판단 | 행정 데이터로 판단 | 사용자가 직접 입력 | 판정이 바뀌는 것만 되묻고, 몰라도 조건부로 안내 |
| 판정 근거 | 공고 링크 | 결과 안내 | 계산 결과 | 조건마다 공고 원문 각주 |
| 다음 행동 | 공고 확인 | 신청 링크 | 신청 링크 | 마감 D-day, 서류·단계 체크리스트 |
| 커버리지 | 넓음 | 넓음 | 복지 중심 | 좁음(검수된 20~30건) |

기존 서비스가 "무엇이 있는지"를 보여준다면, 우리는 "내가 되는지, 왜 그런지, 뭘 해야 하는지"를 대화로 풀어준다.
커버리지가 좁은 건 약점으로 인정하고, 대신 모든 판정 문장이 원문으로 검증된다는 점을 강조한다.

## 목표

| 목표 | 기준 |
| --- | --- |
| G1 빠른 발견 | 폼 제출 직후 1차 결과 카드. 처음 접속부터 첫 결과까지 2분 이내 |
| G2 판단 가능성 | 모든 추천에 충족·미충족·미확인 조건을 원문 근거와 함께 |
| G3 행동 연결 | 정책마다 마감 D-day, 서류, 신청 단계 체크리스트 |
| G4 신뢰 | 모든 정책에 공식 출처와 최종 확인일, 모든 판정에 원문 각주 |
| G5 개인정보 최소화 | 이름·주민번호·서류를 받지 않고, 세션 종료 시 입력 정보를 버린다 |

## 비목표

- 신청서 대리 제출, 정부 사이트 로그인
- 최종 자격 판정이나 수급 보장
- 전국 지원제도 실시간 수집
- 행정 의무 안내(전입신고 등). 판정 근거 품질에 집중하기 위해 범위에서 뺐다
- 문자·카카오톡 푸시 알림

## 사용자 흐름

1. **온보딩 폼 (30초)** — 나이, 거주지, 현재 상태, 관심 분야를 필수로, 가구 소득 구간을 선택으로. 소득에는 "잘 모르겠어요"가 있다.
2. **첫 질문** — 큰 입력창과 예시 칩. 질문 없이 "바로 찾아보기"도 가능.
3. **즉시 1차 결과** — 규칙 엔진이 먼저 카드 3~5개를 띄우고, 이어서 AI 설명이 스트리밍된다. 문장마다 각주.
4. **후속 질문으로 좁히기** — 판정이 바뀌는 정보만 한 번에 하나씩. 답하면 카드 상태가 그 자리에서 갱신. 건너뛸 수 있다.
5. **자유 대화** — "저 다음 학기 휴학해요" 같은 말로 프로필이 바뀌면 변경 사항을 표시하고 재계산.
6. **정책 상세** — 조건별 판정표, 혜택, 마감, 서류, 신청 단계, 공식 링크, 확인일.
7. **체크리스트** — 서류·단계 체크 항목. 마지막 항목은 공식 신청 페이지 이동.
8. **관련 질문 칩 (P1)** — 다음 질문 제안.

### 예외 흐름

| 상황 | 처리 |
| --- | --- |
| 정보 부족 (소득 모름 등) | 단정하지 않고 "확인이 필요해요" + 조건부 문장 |
| 조건 미충족 | 어떤 조건이 안 맞는지 원문과 함께 설명하고 대안 정책 제시 |
| 마감됨 | 기본 결과에서 제외. 직접 물으면 마감 사실과 다음 공고 확인 방법 |
| 결과 없음 | 데이터 범위를 밝히고, 조건을 넓히는 방법과 온통청년 링크 |
| 범위 밖 질문 | 행정 의무, 법률 상담은 다루지 않는다고 짧게 안내 |

## 일정이 밀릴 때 빼는 순서

1. 정책 비교 (P1)
2. 관련 질문 칩을 고정 문구 3개로 대체
3. 체크리스트 체크 상태 유지 기능 (목록 표시만 남김)
4. 상세 패널을 카드 펼침으로 단순화

P0 중 **원문 각주, 후속 질문, 즉시 결과**는 끝까지 지킨다.

| 재배포 | 14:30 동결 이후에는 버그 수정만. 올린 뒤 배포 주소에서 데모 경로를 한 번 통과시킨다 | 시작 파일 캐시 때문에 예전 화면이 보일 수 있다 |

## LLM 사용 전제

캠프에서 **Claude 또는 GPT**를 제공한다. 둘 중 무엇을 쓸지, 호출 한도가 어떻게 되는지는 10:30까지 백엔드B가 확인해 정한다.

| 항목 | 방침 |
| --- | --- |
| 모델 교체 가능성 | 모델을 바꿔도 동작이 깨지지 않게, 호출하는 곳을 한 군데로 모은다. 모델 이름을 여러 모듈에 흩어 두지 않는다 |
| 호출 지점 | 메시지 해석(AI A), 예외 조건 판정(AI B), 답변 작성(AI A) 세 곳뿐. 그 밖에서 모델을 부르지 않는다 |
| 출력 형식 | 정해진 형식으로 강제한다. 형식이 깨지면 한 번 재시도하고, 또 실패하면 미확인으로 두고 진행한다 |
| 호출 한도 | 한도가 빡빡하면 후보 정책 수를 줄이거나 예외 조건 판정을 상위 3개 정책으로 제한한다 |
| 키 관리 | 키는 각자 로컬 환경 변수에. 채팅이나 커밋으로 공유하지 않는다 |
| 날짜 | 모델에게 날짜를 계산시키지 않는다. D-day는 코드가 계산한다 |

## 성공 지표 (당일 측정)

| 지표 | 정의 | 목표 | 측정 |
| --- | --- | --- | --- |
| 추천 정확도 | 대표 프로필 상위 3개 중 정답 정책 비율 | 80% 이상 | 백엔드A 채점 (정답셋 비공개) |
| 근거 없는 조건 | 공고에 없는 자격 조건 출력 건수 | 0건 | 프로필 5개 × 예외 흐름 3개 수동 점검 (AI B) |

| 출처·확인일 표시 | 출력 정책 중 둘 다 있는 비율 | 100% | 자동 점검 |
| 첫 카드 표시 | 폼 제출 → 카드 표시 | 2초 이내 | 데모 경로 실측 |
