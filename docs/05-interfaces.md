## 2. 규칙 엔진 → 서버

| 항목 | 내용 |
| --- | --- |
| 후보 목록 | 관심 분야가 겹치고 마감되지 않은 정책 번호 목록, 정렬된 순서로 |
| 정책별 규칙 조건 결과 | 조건 이름, `met`/`unmet`/`unknown`, 근거 발췌, 출처 |
| 마감 정보 | 마감일, D-day, 배지 문구, 임박 여부 |
| 미확인 항목 목록 | 정책별로 어떤 프로필 항목이 비어서 판정이 안 되는지 |
| 표시 구분 | 기본 표시 5개와 접힌 `unlikely` 개수 |

## 3. 메시지 해석(AI A) → 서버

| 항목 | 값 |
| --- | --- |
| 의도 | `find_policy`, `policy_question`, `compare`, `result_only`, `out_of_scope`, `smalltalk` 중 하나 |
| 프로필 변경 | 항목 이름, 값, 시점(`current` 또는 `planned`). 여러 개 가능 |
| 추가 항목 답변 | 항목 이름과 값. 묻지 않았어도 말했으면 반영 |
| 관심 분야 변경 | 추가할 분야, 제외할 분야 |
| 언급된 정책 | 정책 번호. 특정 정책 질문일 때 |

## 4. 예외 조건 판정(AI B) → 서버

| 항목 | 기준 |
| --- | --- |
| 조건 요약 | 20자 이내 명사형 |
| 결과 | `met`, `unmet`, `unknown` |
| 발췌 | 원문의 연속된 부분 그대로, 10~150자, 조건당 1개 |
| 필요한 추가 항목 | `unknown`일 때만. 추가 항목 이름 또는 "공고 확인 필요" |

## 5. 답변(AI A) → 서버 → 프론트

| 항목 | 기준 |
| --- | --- |
| 답변 조각 | 문장 단위. 글자 단위로 쪼개지 않는다 |
| 각주 번호 매핑 | 답변 문장의 각주 번호 ↔ 조건 결과의 발췌. 서버가 준 번호만 쓴다 |

새로운 발췌를 만들지 않는다. 서버가 넘긴 조건 결과의 발췌에만 연결한다.

## 6. 어긋났을 때 누가 이기는가

| 충돌 | 기준 |
| --- | --- |
| 규칙 조건 vs AI 조건 (같은 내용) | **규칙 조건**을 따른다 |
| 폼 값 vs 대화 값 | **대화 값**을 따른다 |
| AI 요약 vs 공고 원문 | **원문**을 보여준다 |
| 문서 vs 코드 | **문서**가 기준. 문서를 먼저 고치고 구현한다 |
| 판정 상태를 AI가 다르게 말함 | 상태는 **코드**가 확정한다. AI는 설명만 |

## 7. 공통 금지 사항

- 공고에 없는 금액, 날짜, 조건을 화면에 보여주지 않는다. 금액과 날짜는 데이터 필드에서만 가져온다.
- "대상입니다", "받을 수 있어요", "확실히" 같은 확정 표현을 쓰지 않는다.
- 이름, 연락처, 주민등록번호, 계좌번호를 받거나 저장하지 않는다.
- 각주 없는 판정 문장을 출력하지 않는다.
- AI에게 날짜를 계산시키지 않는다.
- 프로필 항목 표에 없는 항목을 대화에서 묻지 않는다.
