# 04. 정책 데이터 규격

> 출처: PRD v2 11장, 역할별 설계서 3-1~3-3. 소유: 백엔드A. **10:30 확정.**
> 사전 준비는 스프레드시트로 하고, 본선 당일 데이터 파일로 변환한다.

## 1. 정책 데이터 필드

| 필드 | 설명 | 예시 |
| --- | --- | --- |
| `id` | 정책 고유 번호 | `SEOUL-001` |
| `title` | 정책명. 공고 제목 그대로 | |
| `agency` | 담당 기관 | 서울특별시 |
| `category` | 분야. 복수 가능 | `living`, `job` |
| `source_url` | 공고 원문 주소 | |
| `apply_url` | 신청 페이지 주소 | |
| `checked_at` | **사람이** 원문을 확인한 날 | 2026-09-19 |
| `fetched_at` | 크롤링으로 받아온 날. 사람 확인과 구분한다. 수동 수집이면 비움 | 2026-09-20 |
| `source_kind` | `manual`(사람이 수집·검수) 또는 `crawled`(크롤링, 검수 전) | `manual` |
| `data_status` | `verified`, `recheck`, `closed`, `upcoming` | `verified` |
| `apply_start` | 접수 시작일 | 2026-09-01 |
| `apply_end` | 마감일. **비우면 상시 접수** | 2026-10-02 |
| `age_min` / `age_max` | 나이 범위 (만 나이) | 19 / 34 |
| `regions` | 대상 지역 | 서울 / 전국 / 자치구명 |
| `statuses` | 대상 신분 | 재학, 휴학, 졸업예정, 구직 |
| `income_max_pct` | 기준 중위소득 상한 %. **비우면 소득 조건 없음** | 150 |
| `extra_conditions` | 대화로 물어야 하는 추가 조건 | 주거 형태: 월세 |
| `exceptions_text` | 제외 대상·예외 조건 원문 | |
| `benefit` | 혜택 요약 | 월 20만원, 최대 10개월 |
| `documents` | 필요 서류. 줄마다 하나 | |
| `steps` | 신청 단계. 순서대로 줄마다 하나 | |
| `raw_text` | 판정에 쓸 공고 원문 핵심 발췌 전체 | |
| `condition_sources` | 조건별 근거 문장. 규칙 조건의 각주로 쓴다 | 나이: "만 19세 ~ 39세 이하 청년" |

- 확인일로부터 **14일**이 지나면 `recheck`으로 보고 카드에 재확인 필요를 표시한다.
- 마감이 지난 정책은 `closed`로 두고 기본 결과에서 뺀다.
- **`raw_text`는 공고 문장을 그대로 복사한다. 요약하거나 고쳐 쓰면 인용 검증이 깨진다.**

## 2. 작성 규칙

| 필드 | 규칙 |
| --- | --- |
| `id` | 지역-일련번호. 서울시는 `SEOUL`, 중앙은 `GOV` |
| 날짜 전부 | `YYYY-MM-DD`. 시간은 적지 않음 |
| `apply_end` | 상시 접수면 비움. "예산 소진 시까지"도 비우고 `raw_text`에 원문 포함 |
| `age_min` / `age_max` | 만 나이 기준. 공고가 출생연도로 쓰면 9/20 기준 만 나이로 바꾸고 원문은 `raw_text`에 그대로 |
| `regions` | 서울, 전국, 또는 자치구명 |
| `statuses` | 프로필 신분 5개 값 중 해당하는 것 전부. 공고가 "대학생"이라고만 하면 재학만 넣고, 휴학 포함 여부가 불분명하면 `exceptions_text`에 해당 문장을 옮김 |
| `income_max_pct` | 기준 중위소득 % 숫자만. 건강보험료 기준 등 다른 방식이면 비우고 `exceptions_text`로 |
| `extra_conditions` | "항목: 필요한 값" 형식. 항목은 `docs/01-glossary-profile.md` 3장에 있는 것만. 예: 주거 형태: 월세 |
| `exceptions_text` | 위 필드로 표현 못 하는 제외 대상·예외 문장을 원문 그대로 |
| `raw_text` | 자격, 제외 대상, 혜택, 신청 기간, 서류, 절차 부분을 원문 그대로 복사. 표는 한 줄씩 풀어 씀 |
| `documents` | 서류명만 줄마다 하나. 발급처가 공고에 있으면 괄호로 |
| `steps` | 공고에 있는 단계만, 순서대로 |
| `checked_at` | 사람이 실제로 원문을 확인한 날. **크롤링 시각을 넣지 않는다** |
| `fetched_at` | 크롤링이 채운다. 사람이 손대지 않는다 |
| `source_kind` | 크롤링으로 들어온 행은 `crawled`. 검수를 통과시킬 때 `manual`로 바꾸고 `checked_at`을 채운다 |
| `condition_sources` | 나이·지역·신분·소득 각 조건에 대응하는 `raw_text` 안의 문장을 그대로 옮김 |

## 2-1. 크롤링으로 들어온 데이터 (최소 구현)

백엔드가 공고 수집을 최소 구현으로 넣는다. 취급 규칙은 `docs/00-overview.md`의 "크롤링" 절이 기준이고, 데이터 쪽 규칙은 이렇다.

| 규칙 | 내용 |
| --- | --- |
| 결과에 나가지 않는다 | `source_kind`가 `crawled`인 행은 후보에서 제외한다. 검수를 통과해 `manual`이 되고 `checked_at`이 채워진 뒤에만 후보가 된다 |
| `raw_text`를 손대지 않는다 | 크롤링한 원문을 그대로 저장한다. 태그 제거와 공백 정리까지만 허용하고 **요약·재작성·문장 다듬기는 금지**한다. 한 글자가 달라지면 발췌 대조가 전건 실패한다 |
| 검수 절차는 같다 | 크롤링으로 들어왔다고 검수를 건너뛰지 않는다. 4장 체크리스트를 그대로 통과해야 한다 |
| 덮어쓰지 않는다 | 이미 검수된 행을 크롤링 결과로 자동 갱신하지 않는다. 사람이 비교하고 바꾼다. 자동 덮어쓰기는 검수된 `raw_text`를 조용히 깨뜨린다 |
| 실패를 흡수한다 | 수집 실패는 로그만 남기고 넘어간다. 서비스 동작에 영향을 주지 않는다 |

**데모 데이터는 전부 `manual`이어야 한다.** 발표 전에 `source_kind`가 `crawled`인 행이 결과에 섞이지 않는지 확인한다.

## 3. 수집 기준

| 기준 | 내용 |
| --- | --- |
| 출처 | 서울시·중앙부처·공공기관의 **공식 공고 원문만**. 블로그, 커뮤니티, 뉴스 기사는 참고만 하고 출처로 쓰지 않음 |
| 대상 | 서울 거주 만 19~24세 대학생·휴학생·졸업예정자·취업준비생이 받을 가능성이 있는 제도 |
| 시기 | 9/20 기준 접수 중, 상시 접수, 또는 10월 중 접수 시작 |
| 제외 | 교내 공지, 특정 기업 채용, 자치구 한정 정책(데모 다양성용으로 2건까지 허용) |

### 분야별 목표 건수

| 분야 | 목표 | 비고 |
| --- | --- | --- |
| 장학·교육 | 5 | |
| 생활비 | 5 | 소득 기준 있는 것 포함 |
| 취업·훈련 | 6 | 데모 핵심 |
| 교통·통신·문화 | 5 | 소득 무관 위주 |
| 주거 | 5 | 데모 6단계용, 주거 형태 조건 있는 것 포함 |
| 합계 | 26 | 최소 20 |

### 데이터 전체 조건 (이게 데모 성패를 가른다)

- 9/20 기준 **접수 중 또는 상시 접수 15건 이상**
- **소득 조건 없는 정책 30% 이상** — 소득을 모르는 사용자에게도 `likely`가 나오게 하기 위함
- 추가 항목(주거 형태, 남은 학기 등) 조건이 있는 정책 **5건 이상** — 후속 질문 시연용
- 데모 프로필에서 `unlikely`가 나오는 정책 **2건 이상** — 대안 흐름 시연용

## 4. 검수 체크리스트 (정책마다)

- [ ] `source_url`을 열었을 때 공고 원문이 바로 보인다
- [ ] 마감일이 원문과 같다
- [ ] 나이, 지역, 신분, 소득 필드가 원문과 모순되지 않는다
- [ ] `raw_text`가 원문과 글자까지 같다 (복사 붙여넣기 확인)
- [ ] `benefit`의 금액이 원문에 있다
- [ ] 필드로 못 옮긴 조건이 `exceptions_text`에 빠짐없이 있다
- [ ] `condition_sources`의 문장이 `raw_text` 안에 그대로 있다
- [ ] 다른 사람 1명이 교차 확인했다

## 5. 규칙 조건 판정 기준

| 조건 | 충족(`met`) | 미충족(`unmet`) | 미확인(`unknown`) |
| --- | --- | --- | --- |
| 나이 | `age_min` 이상 `age_max` 이하 | 범위 밖 | 경계 나이이고 공고에 기준일이 따로 있을 때 |
| 지역 | `regions`에 서울 또는 전국 포함, 자치구 정책은 자치구 일치 | 서울 외 거주인데 서울 정책, 다른 자치구 | 자치구 정책인데 자치구 미선택 |
| 신분 | `statuses`에 현재 상태 포함 | 미포함 | 해당 없음 |
| 소득 | 사용자 구간 상한 ≤ 기준 | 사용자 구간 하한 ≥ 기준 | 구간이 기준에 걸침, 또는 `unknown` |
| 추가 항목 | 답변이 필요한 값과 같음 | 다름 | 아직 묻지 않았거나 건너뜀 |

- `income_max_pct`가 비어 있으면 소득 조건은 판정표에 표시하지 않는다.
- 소득 예: 기준 150%, 사용자 `100_150` → 충족. 기준 120%, 사용자 `100_150` → 미확인.
- 각 규칙 조건에는 `condition_sources`의 문장을 발췌로 연결한다.

| --- | --- |
