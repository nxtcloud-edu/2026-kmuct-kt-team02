## 2. 운영 원칙

- **정답셋은 백엔드A가 만들고 AI A·B에게 공개하지 않는다.** 만든 사람이 채점하지 않아야 지표가 의미 있다.
- **프론트가 1명이라 가장 큰 병목이다.** 백엔드B는 API가 끝나는 대로 프론트의 연결 작업을 맡는다.
- 정책 데이터 수집은 5명이 5~6건씩 나누고, 형식 검토는 백엔드A가 한다.
- 12:00, 14:00에 진행 상황을 점검하고 늦으면 `docs/00-overview.md`의 "빼는 순서"대로 즉시 범위를 줄인다.
- **실제 구현 시간은 약 4시간이다.** 완벽함보다 P0 완성이 우선.

| AI A | 메시지 해석·후속 질문·답변 프롬프트 문안 초안(글로만), 데모 시나리오 대본, 경쟁 서비스 직접 사용과 캡처 |

공식 진행표에 우리 작업을 얹은 것이다. 왼쪽이 대회 일정, 오른쪽이 우리가 그 시간에 하는 일.

| 09:00~10:30 | 아이디어 빌딩 멘토링 | PRD가 이미 있으므로 이 시간에 **멘토 피드백 + KIRO Spec 입력 + 데이터 필드·API·인터페이스 확정** |

| 10:30~12:00 | 개발 멘토링 1 | 역할별 구현 시작 |

### 시각에서 읽어야 할 것

| 사실 | 뜻하는 것 |
| --- | --- |
| 구현은 **10:30에 시작**한다 | 09:00~10:30은 멘토링 시간이다. 이 시간에 코드를 쓰려 하지 말고 Spec과 인터페이스를 확정하는 데 쓴다 |
| 개발 창은 10:30~15:00 | 식사 시간을 포함해 약 4시간 30분. 식사 중 개발이 가능해 실질 구현 시간은 약 4시간 |
| 배포도 개발 멘토링 2 안에 | 15:00 이후에는 배포를 손대지 않는다 |
| 제출 마감은 **17:30**이지 17:00이 아니다 | 발표 준비 종료(17:00)와 제출 마감(17:30) 사이 30분이 마지막 여유다. 이 30분을 계획에 넣지 않는다 |
| 발표가 두 조로 나뉜다 | 우리 순서는 17:40에 정해진다. **17:50에 바로 할 수 있는 상태로 준비한다** |
| 발표까지 대기가 길 수 있다 | 19:10 조가 되면 데모 환경을 두 시간 넘게 유지해야 한다. 세션 만료와 배포 상태를 발표 직전에 다시 확인한다 |
