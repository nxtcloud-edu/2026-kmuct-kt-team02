# 역할별 상세 설계서 전문 (참고용)

> steering에는 공통(1장) + 내 파트(6장 AI B)만 요약·상세로 들어가 있다.
> 이 파일은 다른 역할 장의 전문을 보관하는 참고 문서다. 필요할 때 `#File`로 불러 쓴다.

## 2장 프론트엔드 (전문)

### 목표
사용자가 30초 안에 폼을 끝내고, 결과를 기다리는 느낌 없이 카드와 답변이 흘러나오고, 어떤 판정이든 한 번 눌러서 원문 근거를 볼 수 있는 화면.

### 담당 범위
온보딩, 홈, 대화 결과, 각주 팝오버, 정책 상세 패널, 체크리스트, 반응형, 접근성, 로딩·오류 상태.

### 2-1. 레이아웃

| 환경 | 구성 |
| --- | --- |
| 데스크톱 (1024px 이상) | 왼쪽 대화 영역(최대 폭 720px), 오른쪽 상세 패널(폭 400px, 카드 선택 시 열림) |
| 모바일 (1024px 미만) | 대화 영역 전체 폭, 상세는 하단 시트(화면 높이 90%까지) |
| 공통 | 상단에 프로필 요약 바 고정, 하단에 입력창 고정 |

발표 시연은 데스크톱 기준으로 다듬고, 모바일은 깨지지 않는 수준까지만.

### 2-2. 화면별 명세

#### 온보딩

| 구성 요소 | 명세 |
| --- | --- |
| 제목 | "지금 받을 수 있는 청년 지원, 30초면 찾아요" |
| 설명 | "기본 정보만 알려주시면 바로 찾아볼게요. 나머지는 대화하면서 여쭤볼게요." |
| 나이 | 숫자 입력, 오른쪽에 "세(만 나이)" |
| 거주지 | 서울 / 서울 외 토글. 서울 선택 시 자치구 드롭다운(선택) |
| 현재 상태 | 5개 선택 버튼 중 하나 |
| 관심 분야 | 6개 칩 복수 선택. "전체" 선택 시 나머지 해제 |
| 가구 소득 | 5개 선택 버튼, 기본 "잘 모르겠어요". 보조 문구 "몰라도 괜찮아요. 소득 기준이 있는 제도는 조건을 알려드려요." |
| 개인정보 안내 | "입력한 정보는 맞춤 안내를 위해 AI 모델로 전송되며 저장되지 않아요." |
| 시작 버튼 | "시작하기". 필수 4개가 채워지기 전엔 비활성 |

#### 홈 (첫 질문)

| 구성 요소 | 명세 |
| --- | --- |
| 입력창 | 화면 중앙, 안내 문구 "지금 상황이나 필요한 걸 편하게 말해 주세요" |
| 예시 칩 4개 | "방학 동안 생활비 지원 받을 수 있는 거 있어?", "취업 준비하는데 도움 되는 제도 알려줘", "자취 시작했는데 월세 지원 있어?", "교통비 아낄 수 있는 방법 있을까?" |
| 바로 찾아보기 | 입력 없이 폼 정보만으로 결과 보기 |

칩을 누르면 그 문장이 바로 전송된다.

#### 대화 결과

| 구성 요소 | 명세 |
| --- | --- |
| 사용자 메시지 | 오른쪽 말풍선 |
| 진행 단계 | 답변 위 한 줄. "정책 찾는 중 → 조건 확인 중 → 정리 중". 현재 단계 강조, 완료 단계 체크 |
| 정책 카드 묶음 | 답변 위에 가로 스크롤(모바일) 또는 2열 그리드(데스크톱). 최대 5개 |
| 답변 본문 | 스트리밍으로 문장 단위로 붙임. 각주 번호는 위첨자 버튼 |
| 후속 질문 | 답변 아래 카드 형태. 질문 한 줄, 이유 한 줄(작은 글씨), 선택지 버튼, "직접 입력", "건너뛰기" |
| 관련 질문 칩 (P1) | 맨 아래 2~3개 |
| 접힌 영역 | "조건이 맞지 않을 수 있는 제도 n개" 접기. 펼치면 unlikely 카드 |

#### 정책 카드

| 요소 | 명세 |
| --- | --- |
| 상태 배지 | 아이콘 + 문구. 색은 보조 수단 |
| 제목, 기관 | 제목 2줄까지, 넘치면 말줄임 |
| 혜택 한 줄 | benefit 첫 문장 |
| 마감 배지 | 마감 임박 D-n / D-n / 오늘 마감 / 상시 접수 / 접수 예정 (시작일) |
| 조건부 문장 | check일 때만. 카드 하단 작은 글씨 |
| 출처 줄 | "출처: 기관명 · 확인일 2026.09.19" |
| 갱신 표시 | 상태가 바뀌면 배지가 0.3초 동안 부드럽게 바뀌고 "업데이트됨" 표시 2초 |

#### 각주 팝오버
발췌문(인용 표시), 기관명, 확인일, "공고 원문 보기" 링크. 바깥을 누르거나 ESC로 닫힘.

#### 정책 상세 패널

| 순서 | 구역 | 명세 |
| --- | --- | --- |
| 1 | 머리 | 제목, 기관, 상태 배지, 마감 배지 |
| 2 | 조건 판정표 | 조건마다 한 줄: 결과 아이콘, 조건 요약, 각주 버튼. 순서는 미충족 → 미확인 → 충족 |
| 3 | 조건부 문장 | check일 때 |
| 4 | 혜택 | benefit 전체 |
| 5 | 신청 기간 | 시작일 ~ 마감일, D-day |
| 6 | 체크리스트 | 아래 참고 |
| 7 | 출처 | 공고 원문 링크, 확인일, 재확인 필요 표시(해당 시) |
| 8 | 고정 안내 | "최종 신청 전 공식 공고에서 다시 확인하세요" |

#### 체크리스트
서류 항목 먼저, 신청 단계 다음. 각 항목에 체크 박스. 마지막 항목은 "공식 신청 페이지로 이동" 버튼. 체크 상태는 세션 동안만 유지.

#### 프로필 요약 바
"만 23세 · 서울 · 재학 · 소득 모름" 형태. 누르면 폼과 같은 항목을 수정하는 작은 창. 대화로 프로필이 바뀌면 바뀐 항목이 2초간 강조되고 "휴학으로 바꿨어요" 같은 안내가 대화에 한 줄 들어간다.

### 2-3. 스트리밍 이벤트별 화면 반응

| 이벤트 | 화면 반응 |
| --- | --- |
| status | 진행 단계 표시 갱신 |
| profile_update | 프로필 바 갱신, 대화에 안내 한 줄 |
| policies | 카드 묶음 갱신. 기존 카드는 자리 유지하고 상태만 바뀜, 새 카드는 뒤에 추가 |
| answer_delta | 답변 본문에 이어 붙임 |
| footnotes | 각주 번호를 발췌와 연결 |
| followup | 후속 질문 카드 표시 |
| related | 관련 질문 칩 표시 |
| done | 진행 단계 숨김, 입력창 활성 |

답변 생성 중에도 입력창은 비활성으로 두고, 후속 질문 버튼은 done 이후에만 누를 수 있다.

### 2-4. 로딩·빈 상태·오류

| 상황 | 화면 |
| --- | --- |
| 첫 결과 대기 | 카드 자리에 뼈대(스켈레톤) 3개 |
| 결과 없음 | "지금 조건으로는 찾은 제도가 없어요" + 넓히는 방법 2개(관심 분야 "전체"로, 거주지 확인) + 온통청년 링크 |
| AI 설명 실패 | 카드는 그대로 두고 "설명을 불러오지 못했어요. 카드에서 조건을 확인해 주세요" + 다시 시도 버튼 |
| 연결 끊김 | "연결이 끊겼어요" + 다시 시도 |
| 세션 만료 | "시간이 지나 처음부터 다시 시작할게요" + 온보딩으로 |
| 민감정보 입력 | 입력창 아래 "주민등록번호나 계좌번호는 입력하지 않아도 돼요" |

### 2-5. 접근성
- 상태 배지는 아이콘 + 문구. 색만으로 구분 금지
- 본문 대비 4.5:1 이상, 모바일 본문 14px 이상
- 모든 버튼·칩·카드에 키보드 포커스 표시. Tab 순서는 화면 읽는 순서와 같게
- 답변 스트리밍 영역은 스크린리더가 새 문장을 읽도록 설정
- 각주 버튼에는 "근거 1번 보기" 같은 읽을 수 있는 이름

### 2-6. 시각 방향
- 차분하고 신뢰감 있는 톤. 흰 배경, 본문은 짙은 회색, 강조색 1개
- 상태 색: likely 초록 계열, check 주황 계열, unlikely 회색 계열(빨강은 마감 임박에만)
- 카드 모서리 12px, 그림자는 약하게. 각주 번호는 강조색 원형
- Perplexity처럼 답변 본문 가독성이 최우선. 줄간격 넉넉하게

### [사전 준비]
- 온보딩, 홈, 대화 결과, 각주, 상세, 체크리스트, 결과 없음 와이어프레임
- 화면별 명세의 문구 최종 확인
- 상태 배지 시안 3종을 팀 외부 3명에게 보여주고 문구 확정
- 사용할 UI 라이브러리와 아이콘 세트 결정
- 데모 시나리오 순서대로 화면 전환 흐름 확인

### 완료 기준
- 데모 시나리오 1~9단계를 화면에서 끊김 없이 진행
- 카드 상태 갱신과 프로필 변경 표시가 눈에 보임
- 모든 각주가 원문 팝오버로 열림
- 결과 없음, AI 실패, 연결 끊김 화면이 동작
- 키보드만으로 폼 제출과 카드 열기 가능

## 3장 백엔드A · 데이터와 규칙 (전문)

### 목표
검수된 정책 데이터와, AI 없이도 정확한 1차 결과를 1초 안에 내는 규칙 엔진. 추천 정확도를 채점할 정답셋.

### 3-1. 정책 수집 기준

| 기준 | 내용 |
| --- | --- |
| 출처 | 서울시·중앙부처·공공기관의 공식 공고 원문만. 블로그, 커뮤니티, 뉴스 기사는 참고만 |
| 대상 | 서울 거주 만 19~24세 대학생·휴학생·졸업예정자·취업준비생이 받을 가능성이 있는 제도 |
| 시기 | 9/20 기준 접수 중, 상시 접수, 또는 10월 중 접수 시작 |
| 제외 | 교내 공지, 특정 기업 채용, 자치구 한정 정책(데모 다양성용으로 2건까지 허용) |

#### 분야별 목표 건수

| 분야 | 목표 | 비고 |
| --- | --- | --- |
| 장학·교육 | 5 | |
| 생활비 | 5 | 소득 기준 있는 것 포함 |
| 취업·훈련 | 6 | 데모 핵심 |
| 교통·통신·문화 | 5 | 소득 무관 위주 |
| 주거 | 5 | 데모 6단계용, 주거 형태 조건 있는 것 포함 |
| 합계 | 26 | 최소 20 |

#### 데이터 전체 조건
- 9/20 기준 접수 중 또는 상시 접수 15건 이상
- 소득 조건 없는 정책 30% 이상
- 추가 항목(주거 형태, 남은 학기 등) 조건이 있는 정책 5건 이상 → 후속 질문 시연용
- 데모 프로필에서 unlikely가 나오는 정책 2건 이상 → 대안 흐름 시연용

### 3-2. 스프레드시트 작성 규칙

| 필드 | 작성 규칙 |
| --- | --- |
| id | 지역-일련번호. 서울시는 SEOUL, 중앙은 GOV |
| 날짜 | 모두 YYYY-MM-DD. 시간은 적지 않음 |
| apply_end | 상시 접수면 비움. "예산 소진 시까지"도 비우고 raw_text에 원문 포함 |
| age_min / age_max | 만 나이 기준. 공고가 출생연도로 쓰면 9/20 기준 만 나이로 바꾸고, 원문은 raw_text에 그대로 |
| regions | 서울, 전국, 또는 자치구명 |
| statuses | 1-2의 5개 값 중 해당하는 것 전부. 공고가 "대학생"이라고만 하면 재학만 넣고, 휴학 포함 여부가 불분명하면 exceptions_text에 해당 문장을 옮김 |
| income_max_pct | 기준 중위소득 % 숫자만. 건강보험료 기준 등 다른 방식이면 비우고 exceptions_text로 |
| extra_conditions | "항목: 필요한 값" 형식. 항목은 1-2 추가 항목 표에 있는 것만. 예: "주거 형태: 월세" |
| exceptions_text | 위 필드로 표현 못 하는 제외 대상·예외 문장을 원문 그대로 |
| raw_text | 자격, 제외 대상, 혜택, 신청 기간, 서류, 절차 부분을 원문 그대로 복사. 고쳐 쓰거나 요약하지 않음. 표는 한 줄씩 풀어 씀 |
| documents | 서류명만 줄마다 하나. 발급처가 공고에 있으면 괄호로 |
| steps | 신청 단계를 순서대로 줄마다 하나. 공고에 있는 단계만 |
| checked_at | 실제로 원문을 확인한 날 |

### 3-3. 검수 체크리스트 (정책마다)
- [ ] source_url을 열었을 때 공고 원문이 바로 보인다
- [ ] 마감일이 원문과 같다
- [ ] 나이, 지역, 신분, 소득 필드가 원문과 모순되지 않는다
- [ ] raw_text가 원문과 글자까지 같다 (복사 붙여넣기 확인)
- [ ] benefit의 금액이 원문에 있다
- [ ] 필드로 못 옮긴 조건이 exceptions_text에 빠짐없이 있다
- [ ] 다른 사람 1명이 교차 확인했다

### 3-4. 규칙 조건 판정
(steering 02-roles-common 3장 요약에 표 수록)

소득 예: 기준 150%, 사용자 "100~150%" → 충족. 기준 120%, 사용자 "100~150%" → 미확인.

각 규칙 조건에는 raw_text 중 해당 문장을 발췌로 연결한다. 연결할 문장을 찾기 위해 스프레드시트에 "조건별 근거 문장" 열을 추가해 사전에 채워 둔다. [사전 준비]

### 3-5. 후보 선정과 표시
1. 후보: 관심 분야가 하나 이상 겹치고(전체 선택 시 모두), 데이터 상태가 마감이 아닌 정책
2. 판정 상태를 매긴다
3. 기본 표시: likely와 check 중 정렬 상위 5개
4. 접힌 영역: unlikely 중 정렬 상위 3개
5. likely와 check가 0개면 결과 없음 흐름

### 3-6. 정렬

| 순서 | 기준 |
| --- | --- |
| 1 | 판정 상태: likely → check → unlikely |
| 2 | 마감 7일 이내(마감 임박) 먼저 |
| 3 | 마감일 빠른 순. 상시 접수는 뒤, 접수 예정은 그 뒤 |
| 4 | 관심 분야 일치 수 많은 순. 최근 대화에서 언급된 분야 우선 |
| 5 | id 순 (동점 처리) |

### 3-8. 미확인 항목 목록 (후속 질문 재료)
정책마다 미확인 조건 중 1-2 표의 항목(나이 경계, 자치구, 소득, 추가 항목)을 목록으로 내보낸다. AI A가 이 목록으로 어떤 질문을 할지 고른다.

### 3-9. 대표 프로필과 정답셋 [사전 준비]
(프로필 표는 steering에 수록)

정답셋 작성 방법:
1. 프로필마다 모든 정책에 대해 기대 판정 상태를 적는다
2. 그중 "상위 3개에 꼭 나와야 할 정책"을 3개 고른다
3. 판단 근거가 된 원문 문장을 함께 적는다
4. 정답셋은 AI A·B에게 공개하지 않는다

채점:
- 추천 정확도 = 프로필별 상위 3개 중 정답 정책 수 합계 ÷ 15
- 판정 일치율 = 기대 상태와 실제 상태가 같은 정책 수 ÷ 전체
- 13:00~14:30에 한 번, 14:30 동결 직전에 한 번 채점

### 완료 기준
- 정책 20건 이상 변환, 검수 체크리스트 전부 통과
- 규칙 판정이 P1~P5에서 정답셋과 일치
- 폼 제출 후 1차 결과 1초 이내
- 추천 정확도 80% 이상

## 4장 백엔드B · API와 통합 (전문)

### 목표
각 모듈을 하나의 흐름으로 묶고, 어떤 모듈이 실패해도 사용자 화면이 멈추지 않게 하는 서버. 배포와 통합 일정 관리.

### 4-1. API 명세

#### POST /session

| 구분 | 내용 |
| --- | --- |
| 받는 것 | 기본 프로필 5개 항목 |
| 돌려주는 것 | 세션 번호, 정리된 프로필, 규칙 기반 정책 결과, 첫 후속 질문(있으면) |
| 검증 | 필수 항목 누락, 허용 값 밖 → 입력 오류 |
| 시간 목표 | 1초 이내 |

#### POST /chat

| 구분 | 내용 |
| --- | --- |
| 받는 것 | 세션 번호, 메시지 또는 후속 질문 답변(항목과 값), 건너뛰기 여부 |
| 돌려주는 것 | 스트리밍 이벤트 |
| 검증 | 세션 없음 → 세션 만료 오류. 빈 메시지 → 입력 오류 |

#### GET /policies/{id}
정책 전체 정보와 현재 세션 기준 판정 결과. 세션 번호를 함께 받는다.

#### PATCH /session/{id}/profile
프로필 수정. 수정 후 규칙 결과를 다시 계산해 돌려준다.

#### 오류 공통

| 경우 | 사용자에게 보일 문구 |
| --- | --- |
| 입력 오류 | 입력한 정보를 다시 확인해 주세요 |
| 세션 만료 | 시간이 지나 처음부터 다시 시작할게요 |
| 서버 오류 | 잠시 문제가 생겼어요. 다시 시도해 주세요 |

### 4-4. 민감정보 마스킹

| 대상 | 판단 기준 | 처리 |
| --- | --- | --- |

가린 값은 AI에도, 기록에도 남기지 않는다.

### 4-5. 데모 안정성
- 데모 경로의 입력별 최종 결과를 저장해 두고, 같은 입력이 오면 저장된 결과를 같은 속도감으로 스트리밍하는 "데모 모드". 켜고 끄는 방법은 팀만 안다
- 발표 30분 전 데모 경로를 5회 실행해 응답 시간 기록
- 14:30~15:00에 데모 전체를 화면 녹화해 백업 영상으로

### [사전 준비]
- API, 이벤트, 오류 문구를 프론트와 함께 확인
- PRD 9장과 이 문서를 KIRO Spec에 넣을 순서 정리
- 캠프 제공 환경 확인 목록: 사용할 수 있는 LLM 종류, 호출 한도, 배포 가능한 서비스, 팀원 계정 공유 방식
- 설문 원본 시트 공개 범위 제한

### 완료 기준
- 데모 경로 전체가 한 번에 동작
- AI 판정을 일부러 끊어도 카드가 규칙 결과로 표시
- 데모 모드 동작, 백업 영상 확보
- 배포 주소에서 팀 외부 3명이 사용 가능

## 5장 AI A · 대화 (전문)

### 목표
사용자가 편하게 말해도 프로필과 의도를 정확히 읽고, 판정이 갈리는 것만 묻고, 결론 먼저·근거는 각주로 답하는 대화.

### 5-1. 메시지 해석

#### 뽑아내야 할 것

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 의도 | 정책 찾기, 특정 정책 질문, 비교 요청, 결과만 보기, 범위 밖, 잡담 | 하나 |
| 프로필 변경 | 1-2의 항목과 값, 시점(현재·예정) | 여러 개 가능 |
| 추가 항목 답변 | 1-2 추가 항목과 값 | 질문하지 않았어도 말했으면 반영 |
| 관심 분야 | 추가·제외할 분야 | |
| 언급된 정책 | 정책 id | 특정 정책 질문일 때 |

#### 해석 기준
- 확실히 말한 것만 반영한다. 추측해서 채우지 않는다
- 미래 계획("다음 학기에 휴학해요")은 시점을 "예정"으로 두고 프로필은 바꾸지 않는다. 대신 "휴학 후 기준으로 볼까요, 지금 기준으로 볼까요?"를 후속 질문으로 붙인다
- 폼 값과 다르게 말하면 대화 값을 따른다
- 숫자 소득("월 200 벌어요")은 구간으로 바꾸지 않는다. 가구 소득 기준과 다르므로 "가구 소득 구간을 알려주시면 더 정확해요"로 연결한다

#### 의도별 동작

| 의도 | 동작 |
| --- | --- |
| 정책 찾기 | 전체 흐름 |
| 특정 정책 질문 | 그 정책 상세 판정 위주로 답변, 카드 하나 강조 |
| 비교 요청 (P1) | 두 정책의 조건·혜택·마감 비교 문단 |
| 결과만 보기 | 후속 질문 생략, 현재 결과 정리 |
| 범위 밖 | "행정 절차나 법률 상담은 아직 도와드리기 어려워요" 한 줄 + 할 수 있는 것 안내 |
| 잡담 | 한 줄 응대 후 정책 찾기 유도 |

#### 해석 테스트 케이스 [사전 준비]

| 입력 | 기대 해석 |
| --- | --- |
| 방학 동안 취업 준비하면서 생활비 지원 받을 수 있는 거 있어? | 정책 찾기, 관심 분야 취업·생활비 |
| 저 이번 달부터 자취해요 월세로 | 추가 항목 주거 형태 월세, 관심 분야 주거 추가 |
| 다음 학기에 휴학할 거예요 | 상태 휴학(예정), 프로필 유지, 확인 질문 |
| 사실 저 졸업했어요 | 상태 졸업 후 구직으로 변경 |
| 두 번째 거랑 세 번째 거 비교해줘 | 비교 요청, 표시 순서로 정책 특정 |
| 그냥 결과만 보여줘 | 결과만 보기 |
| 전입신고 어떻게 해? | 범위 밖 |
| 부모님이랑 같이 살아요 | 주거 형태 부모님 집 |
| 월 150 벌어요 | 변경 없음, 가구 소득 안내 |
| 고마워! | 잡담 |

### 5-2. 후속 질문 선택

#### 고르는 기준 (순서대로)
1. 백엔드A가 준 미확인 항목 목록을 모은다. 이미 물었거나 건너뛴 항목은 뺀다
2. 항목마다, 답에 따라 상태가 바뀔 수 있는 표시 중 정책 수를 센다
3. 수가 가장 많은 항목을 고른다
4. 같으면 더 위에 있는 정책에 영향을 주는 항목
5. 그래도 같으면 1-2 표의 순서

고를 항목이 없으면 묻지 않는다. 한 턴에 하나만 묻는다. 사용자가 "결과만 보기" 의도를 보이면 그 세션에서는 먼저 묻지 않는다.

#### 항목별 질문 문구 (화면 문구로 고정)

| 항목 | 질문 | 이유 문구 | 선택지 |
| --- | --- | --- | --- |
| 가구 소득 | 가구 소득이 어느 정도인지 아세요? | ○○ 등 n개 제도가 소득 기준으로 갈려요 | 소득 구간 5개 |
| 자치구 | 어느 구에 사세요? | 구에서 하는 지원이 있어요 | 자주 쓰는 구 5개 + 직접 입력 |
| 주거 형태 | 지금 어떻게 지내고 계세요? | 월세 지원은 주거 형태에 따라 달라요 | 부모님 집, 월세, 전세, 기숙사 |
| 서울 거주 기간 | 서울에 산 지 얼마나 되셨어요? | 거주 기간 조건이 있는 제도가 있어요 | 6개월 미만, 6개월~1년, 1년 이상 |
| 남은 학기 | 졸업까지 몇 학기 남았어요? | 졸업예정자 대상 제도가 있어요 | 1학기, 2학기 이상 |
| 구직 기간 | 구직 활동한 지 얼마나 됐어요? | 구직 기간 조건이 있어요 | 6개월 미만, 6개월 이상 |
| 고용보험 | 일하면서 고용보험에 가입한 적 있어요? | 훈련 지원 조건과 관련 있어요 | 있음, 없음, 모르겠어요 |
| 다른 지원 | 지금 받고 있는 다른 청년 지원금이 있나요? | 중복으로 못 받는 제도가 있어요 | 있음, 없음 |
| 가구원 수 | 함께 사는 가족은 몇 명이에요? | 소득 기준이 가구원 수로 달라져요 | 1인~4인 이상 |
| 직전 학기 성적 | 직전 학기 성적이 공고 기준 이상인가요? | 성적 조건이 있는 장학금이 있어요 | 기준 이상, 기준 미만, 모르겠어요 |

이유 문구의 ○○와 n은 실제 영향받는 정책명과 수로 채운다. 문장 자체를 AI가 새로 만들지 않는다 (P1에서만 맥락에 맞게 다듬기 허용).

### 5-3. 답변 구성

| 순서 | 내용 | 기준 |
| --- | --- | --- |
| 1 | 요약 | 한 문장. "신청 가능성이 높은 제도 n개, 확인이 필요한 제도 n개를 찾았어요." |
| 2 | 정책별 설명 | 표시 순서대로 최대 5개, 정책당 1~2문장. 왜 맞는지 또는 무엇이 남았는지 |
| 3 | 조건 안내 | check가 있으면 남은 조건을 한 문장으로 묶어 안내 |
| 4 | 마감 강조 | 마감 임박이 있으면 한 문장 |
| 5 | 고정 문구 | "최종 신청 전 공식 공고에서 다시 확인하세요" |

말투와 길이: 해요체. 과장, 감탄, 이모지 없음. 전체 600자 이내. 정책명은 데이터의 title 그대로.

근거 규칙:
- 판정·조건·금액·날짜가 들어간 문장에는 반드시 각주를 붙인다
- 각주는 AI B와 백엔드A가 넘긴 조건 결과의 발췌에만 연결한다. 새로운 발췌를 만들지 않는다
- 금액과 날짜는 데이터 필드 값만 쓴다
- 판정 상태는 이미 확정된 값을 설명만 한다. 답변에서 상태를 새로 판단하지 않는다

금지 표현: 대상입니다, 받을 수 있어요, 확실히, 무조건, 100%, 보장, 걱정 마세요

결과 없음일 때: "지금 조건으로는 맞는 제도를 찾지 못했어요." + 넓히는 방법 + 우리 데이터 범위 한 줄.

### 5-4. 관련 질문 칩 (P1)

| 상황 | 칩 예 |
| --- | --- |
| check가 있음 | "소득 기준 확인하는 방법 알려줘" |
| unlikely가 있음 | "조건이 안 맞는 이유가 뭐야?" |
| 카드 2개 이상 | "상위 두 개 비교해줘" |
| 마감 임박 있음 | "마감 임박한 것부터 준비 순서 알려줘" |

최대 3개. 이미 물어본 것과 같은 칩은 빼기.

### 5-5. 대화 평가 [사전 준비]

| 번호 | 대화 | 통과 기준 |
| --- | --- | --- |
| C1 | P1 프로필 + 데모 첫 문장 | 요약 문장, 각주 있음, 600자 이내, 금지 표현 없음 |
| C2 | C1 후 소득 질문에 "모르겠어요" | 같은 질문 다시 안 함, 다음 항목으로 |
| C3 | "저 이번 달부터 자취해요" | 프로필 변경 표시, 주거 정책 등장 |
| C4 | "다음 학기에 휴학할 거예요" | 프로필 유지, 확인 질문 |
| C5 | "결과만 보여줘" | 후속 질문 없음 |
| C6 | "전입신고 어떻게 해?" | 범위 밖 안내 한 줄 |
| C7 | 결과 없는 관심 분야 | 결과 없음 안내와 넓히는 방법 |
| C8 | 모든 항목 건너뛰기 | 질문 멈춤, check 결과 정리 |

### 완료 기준
- 해석 테스트 10개 중 9개 이상 기대대로
- 대화 평가 C1~C8 통과
- 답변 첫 문장 3초 이내 시작
- 금지 표현 0건, 각주 없는 판정 문장 0건
