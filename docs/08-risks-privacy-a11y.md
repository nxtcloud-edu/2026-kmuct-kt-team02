## 2. 개인정보

| 원칙 | 내용 |
| --- | --- |
| 수집하지 않는 것 | 이름, 연락처, 주민등록번호, 계좌번호, 서류 원본 |
| 보관 | 입력 정보는 서버 메모리 세션에만. 세션 종료 시 버린다. **데이터베이스에 저장하지 않는다** |
| 고지 | 온보딩에 "입력한 정보는 맞춤 안내를 위해 AI 모델로 전송되며 저장되지 않아요" |
| 마스킹 | 주민번호·계좌번호·전화번호 형식은 AI 전송 전에 가린다 (FR15). 가린 값은 기록에도 남기지 않는다 |
| 기록 | 사용자 메시지 원문과 프로필은 기록하지 않는다. 단계별 소요 시간, 인용 검증 제거 건수, AI 실패 건수만 |
| 설문 원본 | 시트 공개 범위를 제한하고, 발표 자료와 공개 문서에는 비식별 요약만 쓴다. 원본 링크를 공개 문서에 넣지 않는다 |

## 3. 접근성

| 항목 | 기준 |
| --- | --- |
| 상태 구분 | 색 + 문구 + 아이콘. **색만으로 구분 금지** |
| 대비 | 본문 대비 4.5:1 이상 (WCAG AA 수준) |
| 글자 크기 | 모바일 본문 14px 이상 |
| 키보드 | 폼 입력, 질문 답변, 카드 열기가 키보드만으로 가능. Tab 순서는 화면 읽는 순서와 같게 |
| 포커스 | 모든 버튼·칩·카드에 포커스 표시 |
| 스크린리더 | **답변 본문 자체를 자동 낭독 대상으로 두지 않는다.** 진행 단계와 완료만 짧은 상태 메시지로 알린다. 아래 참고 |
| 읽을 수 있는 이름 | 각주 버튼에 "근거 1번 보기" 같은 이름 |

### 스트리밍 영역 처리 (조사 결과로 수정됨)

문장이 붙을 때마다 낭독이 끊기고 다시 시작되면 스크린리더 사용자에게는 읽을 수 없는 화면이 된다.
`docs/research/03-streaming-ux-and-latency.md` 4절 참고.

| 대상 | 어떻게 |
| --- | --- |
| 진행 단계 | 공손한(`polite`) 라이브 리전에서 짧게. "정책 찾는 중", "조건 확인 중", "정리 중" |
| 답변 본문 | 자동 낭독 대상에서 **제외**. 완료 후 사용자가 직접 읽는다 |
| 완료 알림 | 공손한 영역에서 한 줄. "답변 완료. 제도 5개를 찾았어요" |
| 카드 상태 갱신 | 공손한 영역에서 한 번만. 카드마다 알리지 않는다 |
| 오류 | 단호한(`assertive`) 영역 또는 경고 역할. 여기서만 낭독을 끊는다 |
| 라이브 리전 준비 | 갱신이 일어나기 **전에** 페이지에 둔다 |

> 전체 WCAG 준수 검증은 보조기술 수동 테스트와 전문가 검토가 필요하다.
> 여기 적은 것은 하루 안에 지킬 수 있는 최소 기준이다.

## 4. LLM 전송 고지

- 온보딩 화면에 한 줄로 고지한다.
- 전송되는 것: 프로필 값, 사용자 메시지, 후보 정책의 공고 원문
- 전송되지 않는 것: 마스킹된 민감정보, 이름·연락처(애초에 받지 않음)
- 저장되지 않는다는 점을 명시한다.
