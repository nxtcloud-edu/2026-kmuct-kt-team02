# AI 청년 지원제도 추천 서비스 PRD v2

> 팀 소다쿠키 · 2026 국민대 캠타 AI 바이브 코딩 해커톤(키로톤)
> 작성일 2026-09-18 · 본선 2026-09-20
> 팀 구성: 프론트엔드 1 · 백엔드 2 · AI 2

## 1. 핵심 결정

**한 문장**
서울 대학생·취업준비생이 기본 정보를 입력하고 자기 상황을 말하면, AI가 공식 공고를 근거로 받을 수 있는 지원제도를 바로 보여주고, 판정에 필요한 것만 되물으며, 신청까지 해야 할 일을 정리해 주는 대화형 서비스.

**발표용 한 줄**
청년 지원제도를 위한 Perplexity. 모든 판정 문장에 공고 원문 각주가 달린다.

- 핵심 사용자: 서울 거주 만 19~24세 대학생, 휴학생, 졸업예정자, 취업준비생
- P0: 온보딩 폼, 대화 입력, 즉시 1차 결과, 판정을 바꾸는 후속 질문, 조건별 근거와 원문 각주, 조건부 결과, 마감 배지, 정책 상세, 신청 체크리스트, 출처와 확인일
- P1: 정책 비교, 대안 추천 고도화, 관련 질문 칩
- 제외: 자동 신청, 정부 계정 연동, 민감 서류 저장, 전국 실시간 수집, 최종 자격 판정, 행정 의무 안내, 푸시 알림

## 2. 배경과 문제

### 조사 개요
설문 참여 29명. 만 19~24세 96.6%, 대학(원)생 89.7%, 서울 거주 82.8%. 표본이 작고 편의표집이므로 비율을 시장 전체로 일반화하지 않는다.

### 설문 신호

| 신호 | 수치 | 분모 | 제품 반영 |
| --- | --- | --- | --- |
| 늦은 발견 | 18명 90.0% | 경험 응답자 20명 | 입력 즉시 관련 제도를 먼저 보여줌 |
| 알고도 신청 미완료 | 15명 75.0% | 경험 응답자 20명 | 추천에서 끝내지 않고 체크리스트까지 |

| 신뢰 조건: 공식 링크 | 21명 72.4% | 전체 29명 | 모든 판정에 원문 각주 |

### 핵심 문제
지원제도 정보는 여러 기관에 흩어져 있고, 공고문은 조건과 예외가 긴 문장에 섞여 있다. 학생들은 제도를 늦게 알고, 자기가 대상인지 판단하지 못하고, 마감과 서류 준비에서 신청을 멈춘다.

## 3. 사용자와 해결할 일

| 구분 | 대상 | 필요 |
| --- | --- | --- |
| 1차 | 서울 거주 만 19~24세 대학생 | 놓치고 있는 제도와 신청 가능성을 빨리 알고 싶음 |
| 2차 | 휴학생, 졸업예정자, 취업준비생 | 신분이 바뀔 때 맞는 제도를 놓치지 않고 싶음 |

만 25~34세 청년은 설문 근거가 없어 MVP 대상에서 제외.

## 4. 기존 서비스와의 차이

| 항목 | 온통청년 | 정부24 혜택알리미 | 복지로 | 우리 서비스 |
| --- | --- | --- | --- | --- |
| 입력 방식 | 조건 필터·검색 | 본인 인증 기반 | 조건 선택·모의계산 | 짧은 폼 + 자연어 대화 |
| 모르는 정보 처리 | 사용자가 직접 판단 | 행정 데이터로 판단 | 사용자가 직접 입력 | 판정이 바뀌는 것만 되묻고, 몰라도 조건부로 안내 |
| 판정 근거 | 공고 링크 | 결과 안내 | 계산 결과 | 조건마다 공고 원문 각주 |
| 다음 행동 | 공고 확인 | 신청 링크 | 신청 링크 | 마감 D-day, 서류·단계 체크리스트 |
| 커버리지 | 넓음 | 넓음 | 복지 중심 | 좁음(검수된 20~30건) |

기존 서비스가 "무엇이 있는지"를 보여준다면, 우리는 "내가 되는지, 왜 그런지, 뭘 해야 하는지"를 대화로 풀어준다.

## 5. 목표와 비목표

| 목표 | 기준 |
| --- | --- |
| G1 빠른 발견 | 폼 제출 직후 1차 결과 카드가 뜬다. 첫 결과까지 2분 이내 |
| G2 판단 가능성 | 모든 추천에 충족·미충족·미확인 조건을 원문 근거와 함께 |
| G3 행동 연결 | 정책마다 마감 D-day, 서류, 신청 단계를 체크리스트로 |
| G4 신뢰 | 모든 정책에 공식 출처와 최종 확인일, 모든 판정에 원문 각주 |
| G5 개인정보 최소화 | 이름·주민번호·서류를 받지 않고, 세션 종료 시 입력 정보를 버린다 |

**비목표**: 신청서 대리 제출, 정부 사이트 로그인, 최종 자격 판정, 전국 실시간 수집, 행정 의무 안내, 푸시 알림

## 6. 사용자 흐름

1. **온보딩 폼 (30초)** — 나이, 거주지, 현재 상태, 관심 분야 필수 / 가구 소득 선택("잘 모르겠어요" 포함)
2. **첫 질문** — 큰 입력창 + 예시 칩. "바로 찾아보기"도 가능
3. **즉시 1차 결과** — 규칙 엔진이 카드 3~5개 먼저, 이어서 AI 설명 스트리밍. 문장마다 [1][2] 각주
4. **후속 질문으로 좁히기** — 판정이 바뀌는 정보만, 한 번에 하나, 건너뛰기 가능
5. **자유 대화** — 프로필 변경 시 상단 표시 + 결과 재계산
6. **정책 상세** — 조건별 판정표, 혜택, 마감, 서류, 신청 단계, 공식 링크, 확인일
7. **체크리스트** — 서류·단계 체크 항목, 마지막은 공식 신청 페이지 이동
8. **관련 질문 칩 (P1)**

### 예외 흐름

| 상황 | 처리 |
| --- | --- |
| 정보 부족 (소득 모름 등) | "확인이 필요해요" + 조건부 문장 |
| 조건 미충족 | 어떤 조건이 안 맞는지 원문과 함께 설명 + 대안 정책 |
| 마감됨 | 기본 결과에서 제외. 직접 물으면 마감 사실과 다음 공고 안내 |
| 결과 없음 | 데이터 범위 밝히고, 조건 넓히는 방법 + 온통청년 링크 |
| 범위 밖 질문 | 행정 의무, 법률 상담 등은 다루지 않는다고 짧게 안내 |

## 7. 대화 설계 원칙

### 폼과 대화의 역할

| 폼으로 받는 것 | 대화로 묻는 것 |
| --- | --- |
| 나이(만 나이) | 주거 형태(본가·월세·전세·기숙사) |
| 거주지(서울 여부, 자치구) | 거주 기간 |
| 현재 상태(재학·휴학·졸업예정·구직·재직) | 재학 학기, 성적 요건 |
| 관심 분야(복수 선택) | 구직 기간, 고용보험 가입 이력 |
| 가구 소득 구간(선택, 모름 가능) | 다른 지원 중복 수혜 여부 |

폼은 5항목, 30초. 대화 입력이 폼보다 우선한다.

### 후속 질문 규칙
- 고정 개수 제한 없음
- 상위 후보 중 하나 이상의 판정 상태를 바꾸는 정보만 묻는다
- 여러 개면 가장 많은 후보의 판정에 영향 주는 것부터 (선택은 코드, 문장 다듬기는 AI)
- 한 턴에 질문 하나, 선택지 버튼 + 직접 입력 + 건너뛰기
- 판정을 바꾸는 미확인 정보가 없으면 더 묻지 않는다
- 질문마다 "이걸 알면 ○○ 제도 판정이 확정돼요" 이유 한 줄

### 답변 형식
- 결론 먼저, 근거는 각주로
- 판정 관련 문장에는 반드시 원문 각주. 각주 없는 판정 문장은 출력하지 않는다
- "대상입니다" 대신 "신청 가능성이 높아요"
- 끝에 "최종 신청 전 공식 공고에서 다시 확인하세요" 고정

### 신청 가능성 상태

| 상태 | 화면 문구 | 아이콘 | 조건 |
| --- | --- | --- | --- |
| likely | 신청 가능성이 높아요 | ✓ | 모든 필수 조건 충족 |
| check | 확인이 필요해요 | ? | 미충족 없고 미확인 1개 이상 |
| unlikely | 어려울 수 있어요 | ✕ | 필수 조건 1개 이상 미충족 |

색만으로 구분하지 않고 문구와 아이콘을 항상 함께.

### 마감 표시

| 경우 | 배지 | 기본 결과 노출 |
| --- | --- | --- |
| 마감 7일 이내 | 마감 임박 D-n | 노출, 같은 상태 안에서 상단 |
| 마감 8일 이상 | D-n | 노출 |
| 상시 접수 | 상시 접수 | 노출, 같은 상태 안에서 하단 |
| 접수 전 | 접수 예정 (시작일) | 노출 |
| 마감 지남 | — | 제외 |

D-day는 한국 시간 오늘 기준으로 코드가 계산한다. AI는 날짜를 계산하지 않는다.

**정렬**: 상태(likely → check → unlikely) → 마감 임박 순 → 관련도

## 8. MVP 범위와 우선순위

| 우선순위 | 기능 | 근거 |
| --- | --- | --- |
| P0 | 온보딩 폼 | 공통 조건 빠른 수집 |
| P0 | 자연어 대화 입력과 프로필 갱신 | 대화형이 핵심 차별점 |
| P0 | 규칙 기반 즉시 1차 결과 | 늦은 발견 90.0%, 자동 탐색 72.4% |
| P0 | 판정을 바꾸는 후속 질문 | 대상 판단 어려움 50.0% |
| P0 | 조건별 판정과 원문 각주 | 판단 근거 51.7%, 공식 링크 72.4% |
| P0 | 조건부 결과 문장 | 소득 모름 시 결과가 비는 문제 방지 |
| P0 | 마감 배지와 정렬 | 마감 60.0% |
| P0 | 정책 상세와 체크리스트 | 절차 중단 50.0%, 서류 30.0% |
| P0 | 출처와 확인일 | 확인일 58.6% |
| P1 | 관련 질문 칩 / 정책 두 개 비교 / 대안 추천 고도화 | |
| P2 | 비대상 통지문 해석 / 마감 알림 | |

**일정이 밀릴 때 빼는 순서**: 정책 비교(P1) → 관련 질문 칩을 고정 문구 3개로 → 체크리스트 상태 유지 → 상세 패널을 카드 펼침으로

P0 중 원문 각주, 후속 질문, 즉시 결과는 끝까지 지킨다.

### 초기 정책 데이터
- 서울시와 중앙정부 청년 정책 20~30건 수동 검수. 교내 공지 제외
- 분야 순서: 장학·교육, 생활비·현금성, 취업·훈련·인턴, 교통·통신·문화, 주거
- **9/20 기준 접수 중이거나 상시 접수인 정책 최소 15건**
- **소득 조건이 없는 정책 전체의 30% 이상**

## 9. 기능 요구사항 (EARS)

| ID | 요구사항 | 인수 기준 |
| --- | --- | --- |
| FR01 | 온보딩 폼 | THE SYSTEM SHALL 나이, 거주지, 현재 상태, 관심 분야를 필수로, 가구 소득 구간을 선택으로 받는다. 소득에는 "잘 모르겠어요"를 둔다. IF 필수 항목이 비어 있으면 THE SYSTEM SHALL 시작 버튼을 비활성화한다. |
| FR02 | 자연어 해석과 프로필 갱신 | WHEN 사용자가 메시지를 보내면 THE SYSTEM SHALL 관심 분야, 생활 사건, 프로필 변경 정보를 추출한다. IF 추출 값이 기존 프로필과 다르면 THE SYSTEM SHALL 대화 값을 적용하고 변경 사실을 화면에 표시하며 결과를 다시 계산한다. |
| FR03 | 후보 검색 | THE SYSTEM SHALL 공식 출처가 등록되고 마감되지 않은 정책 중 관심 분야가 맞는 것만 후보로 삼고, 상위 3~5개를 반환한다. |
| FR04 | 답 먼저 | WHEN 폼을 제출하거나 첫 메시지를 보내면 THE SYSTEM SHALL 후속 질문보다 먼저 1차 결과 카드를 표시한다. |
| FR05 | 후속 질문 | WHEN 상위 후보 중 하나 이상의 판정이 미확인 정보 하나로 바뀔 수 있으면 THE SYSTEM SHALL 그 정보를 묻는 질문을 한 번에 하나, 선택지·직접 입력·건너뛰기와 함께 제시한다. IF 그런 정보가 없으면 THE SYSTEM SHALL 질문하지 않는다. WHEN 사용자가 건너뛰면 THE SYSTEM SHALL 해당 조건을 미확인으로 유지한다. |
| FR06 | 신청 가능성 상태 | THE SYSTEM SHALL 각 정책을 likely, check, unlikely 중 하나로 표시하고, 문구와 아이콘을 함께 보여준다. |
| FR07 | 조건별 근거와 각주 | THE SYSTEM SHALL 조건마다 충족·미충족·미확인을 표시하고 공고 원문 발췌를 각주로 연결한다. IF 발췌문이 원문에 존재하지 않으면 THE SYSTEM SHALL 그 조건 설명을 출력하지 않고 미확인으로 처리한다. |
| FR08 | 조건부 결과 | IF 미확인 조건이 있고 미충족 조건이 없으면 THE SYSTEM SHALL "○○라면 신청 가능" 형태의 조건부 문장을 카드에 표시한다. |
| FR09 | 마감 표시와 정렬 | THE SYSTEM SHALL 7장 마감 표시 규칙과 정렬 규칙을 따른다. D-day는 코드로 계산한다. |
| FR10 | 정책 상세 | WHEN 카드를 선택하면 THE SYSTEM SHALL 조건별 판정표, 혜택, 마감, 서류, 신청 단계, 담당 기관, 공식 링크, 최종 확인일을 한 화면에 표시한다. |
| FR11 | 신청 체크리스트 | WHEN 상세 화면을 열면 THE SYSTEM SHALL 서류와 신청 단계를 체크 가능한 항목으로 보여주고, 마지막 항목에 공식 신청 페이지 링크를 둔다. |
| FR12 | 출처와 확인일 | THE SYSTEM SHALL 모든 카드와 상세에 공식 출처와 최종 확인일을 표시한다. IF 둘 중 하나라도 없으면 THE SYSTEM SHALL 그 정책을 결과에서 제외한다. |
| FR13 | 대안과 결과 없음 | IF 정책이 unlikely이면 THE SYSTEM SHALL 미충족 조건과 같은 분야의 대안 정책을 제시한다. IF 후보가 없으면 THE SYSTEM SHALL 데이터 범위, 조건을 넓히는 방법, 온통청년 링크를 보여준다. |
| FR14 | 진행 상태 표시 | WHILE AI 응답을 생성하는 동안 THE SYSTEM SHALL "정책 찾는 중 → 조건 확인 중 → 정리 중" 단계를 표시하고 답변을 스트리밍한다. |
| FR15 | 민감정보 차단 | IF 입력에 주민등록번호나 계좌번호 형식이 있으면 THE SYSTEM SHALL AI에 보내기 전에 가리고 입력하지 말라는 안내를 표시한다. |

### 처리 순서
폼 제출 → 규칙 엔진이 후보 걸러 카드 즉시 표시 → 메시지 전송 시 메시지 해석으로 프로필·관심 분야 갱신 → 규칙 엔진 재계산 → 후보 정책 원문 넣어 예외 조건 판정 → 인용 검증 통과한 판정만 남겨 카드 상태 갱신 → 답변 스트리밍 → 후속 질문

- 정책이 20~30건이라 임베딩·벡터 검색은 쓰지 않는다. 규칙 필터로 좁히고 원문을 통째로 넣는다
- 명시 조건은 규칙 엔진이, 문장형 예외 조건만 AI가 판정
- AI 판정이 늦거나 실패해도 규칙 엔진 결과만으로 카드는 보인다

## 12. AI 설계와 가드레일

| AI가 한다 | 코드가 한다 |
| --- | --- |
| 자연어에서 관심 분야·생활 사건·프로필 변경 추출 | 나이·지역·상태·소득 % 판정 |
| 문장형 예외 조건 판정과 원문 발췌 | 마감 D-day 계산과 정렬 |
| 후속 질문 문장 다듬기 | 어떤 정보를 물을지 선택 |
| 답변 설명 작성 | 인용 검증, 출처·확인일 표시, 민감정보 마스킹 |

### 가드레일
- **인용 검증**: AI가 낸 모든 발췌문을 공백 정규화 후 `raw_text`와 대조. 없으면 그 조건은 미확인으로 바꾸고 설명에서 뺀다. 제거 건수는 로그
- **근거 범위 제한**: 프롬프트에 후보 정책 원문만 넣고, 원문에 없는 조건을 만들지 말라고 지시. 출력은 JSON 스키마로 강제
- **단정 금지**: "대상입니다", "받을 수 있습니다" 금지. 상태 문구는 코드가 붙인다
- **원문 우선**: AI 요약과 원문이 다르면 원문을 보여준다
- **실패 시 대체**: AI 응답 시간 초과나 JSON 깨짐 시 규칙 엔진 결과와 원문 링크만으로 카드 표시

## 13. 개인정보와 접근성

### 개인정보
- 이름, 연락처, 주민등록번호, 계좌번호, 서류 원본을 받지 않는다
- 입력 정보는 서버 메모리 세션에만, 세션 종료 시 폐기. DB 저장 없음
- 온보딩 고지: "입력한 정보는 맞춤 안내를 위해 AI 모델로 전송되며 저장되지 않아요."
- 주민번호·계좌번호 형식은 AI 전송 전 마스킹 (FR15)

### 접근성
- 상태는 색 + 문구 + 아이콘
- 본문 대비 WCAG AA 이상, 모바일 본문 14px 이상
- 키보드만으로 폼 입력, 질문 답변, 카드 열기 가능
- 스트리밍 영역은 aria-live

## 15. 데모 시나리오

**프로필**: 만 23세, 서울 거주, 재학 중, 관심 분야 취업·생활비, 소득 "잘 모르겠어요"

1. 온보딩 폼 30초 안에 채우기
2. "방학 동안 취업 준비하면서 생활비 지원 받을 수 있는 거 있어?" 입력
3. 카드 즉시 표시 + 설명 스트리밍. 소득 기준 있는 정책은 "확인이 필요해요" + 조건부 문장
4. 각주 [1] 눌러 공고 원문과 확인일 확인 (신뢰 포인트)
5. 후속 질문 "졸업까지 한 학기만 남았나요?" 버튼 답변 → 카드 상태 변경 (대화형 포인트)
6. "아 저 이번 달부터 자취해요" → 프로필 변경 표시 → 주거 지원 정책 등장
7. 정책 상세 열어 조건별 판정표와 체크리스트. 마감 임박 배지 강조
8. unlikely 정책 열어 미충족 이유와 대안 정책
9. 데이터에 없는 분야(창업 자금) 물어 결과 없음 처리

3, 6, 8, 9번으로 정보 부족·조건 미충족·결과 없음 예외 흐름 모두 시연. 15:00 이전에 데모 녹화 백업.
