# steering 파일 안내

> 이 폴더의 파일은 저장소를 클론한 **전원의 Kiro에 자동 적용**된다(`inclusion: always`인 것만).
> 매 요청마다 컨텍스트에 들어가므로 분량과 적용 범위를 관리한다.
> 이 README 자체는 안내용이고 규칙이 아니다.

## 왜 90번과 91번을 수동으로 바꿨는가

- `90-reference-prd.md` — 310줄을 매 요청에 넣으면 정작 지켜야 할 규칙이 긴 문맥 중간에 묻힌다. 요약은 `00-project-context.md`에, 정식 문서는 `docs/00-overview.md`에 있다.
- `91-role-ai-b.md` — 특정 역할 전용 규칙이 전원에게 적용되면 프론트 담당 Kiro가 인용 검증 작업을 하려 들고, 자기 폴더 밖을 건드린다. 역할 전용 규칙은 그 사람만 불러 쓴다.

## 자기 역할 규칙을 자동 적용하고 싶으면

자기 로컬에서만 해당 파일의 front-matter를 `inclusion: always`로 바꿔 쓴다.
**그 변경을 커밋하지 않는다.** 커밋하면 다른 사람에게도 적용된다.

역할별 상세 명세는 steering이 아니라 각 역할 폴더의 `README.md`에 있다.
본선 당일 Spec 입력으로는 `docs/02-requirements-ears.md` + `docs/01-glossary-profile.md` + 자기 역할 폴더 README를 쓴다.

## 새 steering 파일을 추가할 때

| 성격 | 번호 | 적용 |
| --- | --- | --- |
| 전원이 항상 지킬 규칙 | 00~09 | 자동 |
| 특정 파일을 열 때만 필요한 규칙 | 10~19 | `inclusion: fileMatch` + `fileMatchPattern` |
| 참고 자료, 역할 전용 | 90~99 | `inclusion: manual` |

추가하기 전에 **기존 파일에 넣을 수 없는지 먼저 본다.** 파일이 늘어나는 것보다 한 파일이 정확한 게 낫다.
같은 번호를 두 사람이 쓰지 않도록, 추가하면 이 표를 같이 고친다.

## 값이 어긋날 때

| 충돌 | 기준 |
| --- | --- |
| steering vs `docs/` | **`docs/`가 기준.** steering은 요약이고 `docs/`가 정식 명세다 |
| `90-reference-prd.md` vs `docs/` | `docs/`가 기준. PRD는 작성 당시 기록이다 |
| 문서 vs 코드 | 문서가 기준. 문서를 먼저 고치고 구현한다 |
