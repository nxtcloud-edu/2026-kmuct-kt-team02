# 역할별 상세 설계서 · 1장 공통

> 팀 소다쿠키 · PRD v2 부속 문서
> 기획·설계 문서. 코드, 의사코드, AI 프롬프트 문안은 포함하지 않는다.

## 0. 이 문서 쓰는 법

- 본선 당일 09:00에 각자 PRD 9장(기능 요구사항) + 이 문서 1장(공통) + 자기 역할 장을 KIRO Spec 모드의 요구사항 입력으로 쓴다.
- 역할 장은 "목표 → 담당 범위 → 상세 명세 → 예외 처리 → 완료 기준" 순서.
- 다른 역할과 주고받는 정보는 1장의 인터페이스 표가 기준. 09:30에 확정한 뒤에는 바꾸지 않는다. 꼭 바꿔야 하면 백엔드B에게 알리고 전원 공지.
- 본선 전에 채울 것은 각 장의 [사전 준비] 항목뿐이다.

## 1-1. 용어

| 용어 | 뜻 |
| --- | --- |
| 세션 | 한 사용자의 한 번 사용. 서버 메모리에만 있고 30분 비활성 또는 새로고침 시 폐기 |
| 프로필 | 폼과 대화로 모은 사용자 정보. 기본 항목 5개 + 추가 항목 |
| 후보 | 관심 분야가 맞고 마감되지 않은 정책 |
| 판정 상태 | 정책 단위 결과. likely(신청 가능성이 높아요), check(확인이 필요해요), unlikely(어려울 수 있어요) |
| 조건 결과 | 조건 단위 결과. 충족, 미충족, 미확인 |
| 판정 주체 | 규칙(규칙 엔진) 또는 AI(예외 조건 판정) |
| 조건부 문장 | check 상태일 때 남은 조건을 "○○라면 신청 가능해요"로 풀어쓴 문장 |
| 각주 | 판정 문장에 붙는 번호. 누르면 공고 원문 발췌, 출처, 확인일 |
| 발췌 | 공고 원문에서 그대로 가져온 연속된 문장 일부 |
| 확인일 | 팀이 공고 원문을 마지막으로 확인한 날짜 |
| D-day | 한국 시간 오늘부터 마감일까지 남은 일수 |

## 1-2. 프로필 항목과 허용 값

### 기본 항목 (온보딩 폼)

| 항목 | 필수 | 허용 값 | 비고 |
| --- | --- | --- | --- |
| 나이 | 필수 | 만 나이 숫자 15~39 | 범위 밖 입력은 폼에서 막음 |
| 거주지 | 필수 | 서울(자치구 25개 중 선택 또는 "자치구 선택 안 함"), 서울 외 | 자치구는 선택 입력 |
| 현재 상태 | 필수 | 재학, 휴학, 졸업예정(마지막 학기), 졸업 후 구직, 재직 | 하나만 선택 |
| 관심 분야 | 필수 | 장학·교육, 생활비, 취업·훈련, 교통·통신·문화, 주거, 전체 | 복수 선택 |
| 가구 소득 | 선택 | 기준 중위소득 50% 이하, 50~100%, 100~150%, 150% 초과, 잘 모르겠어요 | 기본값 "잘 모르겠어요" |

### 추가 항목 (대화로 물음)

| 항목 | 허용 값 |
| --- | --- |
| 주거 형태 | 부모님 집, 월세, 전세, 기숙사, 기타 |
| 서울 거주 기간 | 6개월 미만, 6개월~1년, 1년 이상 |
| 남은 학기 | 1학기, 2학기 이상 |
| 구직 기간 | 6개월 미만, 6개월 이상 |
| 고용보험 가입 이력 | 있음, 없음 |
| 다른 지원 수혜 중 | 있음, 없음 |
| 가구원 수 | 1인, 2인, 3인, 4인 이상 |
| 직전 학기 성적 | 기준 이상, 기준 미만, 모름 |

- 모든 항목은 "건너뛰기"가 가능하고, 건너뛴 항목은 미확인으로 남는다.
- 새 추가 항목이 필요하면 백엔드A가 표에 추가하고 전원 공지. 표에 없는 항목은 대화에서 묻지 않는다.

## 1-3. 판정 상태 결정 규칙

| 조건 결과 조합 | 판정 상태 |
| --- | --- |
| 규칙 조건 또는 AI 조건 중 미충족이 1개 이상 | unlikely |
| 미충족 없음, 미확인 1개 이상 | check |
| 모든 조건 충족 | likely |
| AI 판정 실패·시간 초과 | 예외 조건 전체를 미확인으로 두고 위 규칙 적용 |

규칙 조건과 AI 조건이 같은 내용을 다르게 판정하면 **규칙 조건을 따른다**.

| 주는 쪽 | 받는 쪽 | 무엇 | 확정 시각 |

| AI B | 백엔드B | 정책별 예외 조건 판정: 조건 요약, 결과, 발췌, 필요한 추가 항목 | 09:30 형식, 12:00 동작 |

| 프론트 | 전원 | 화면 목업 확인용 주소 | 12:00 |

## 1-5. 공통 금지 사항

- 공고에 없는 금액, 날짜, 조건을 화면에 보여주지 않는다. 금액과 날짜는 데이터 필드에서만 가져온다.
- "대상입니다", "받을 수 있어요", "확실히" 같은 확정 표현을 쓰지 않는다.
- 이름, 연락처, 주민등록번호, 계좌번호를 받거나 저장하지 않는다.

# 다른 역할 요약 (인터페이스 참조용)

## 2장 프론트엔드 (요약)

- 레이아웃: 데스크톱 1024px+ 좌측 대화(최대 720px) + 우측 상세 패널(400px), 모바일은 하단 시트
- 화면: 온보딩, 홈(첫 질문), 대화 결과, 각주 팝오버, 정책 상세 패널, 체크리스트
- 스트리밍 이벤트별 화면 반응: status → 진행 단계, profile_update → 프로필 바 + 대화 안내, policies → 카드 갱신, answer_delta → 본문 이어붙임, footnotes → 각주 연결, followup → 질문 카드, related → 칩, done → 입력창 활성
- 상태 색: likely 초록, check 주황, unlikely 회색 (빨강은 마감 임박만). 색 단독 구분 금지
- 오류 상태: 결과 없음 / AI 설명 실패 / 연결 끊김 / 세션 만료 / 민감정보 입력

## 3장 백엔드A · 데이터와 규칙 (요약)

### 규칙 조건 판정

| 조건 | 충족 | 미충족 | 미확인 |
| --- | --- | --- | --- |
| 나이 | age_min 이상 age_max 이하 | 범위 밖 | 경계 나이이고 공고에 기준일이 따로 있을 때 |
| 지역 | regions에 서울/전국 포함, 자치구 정책은 자치구 일치 | 서울 외 거주인데 서울 정책, 다른 자치구 | 자치구 정책인데 자치구 미선택 |
| 신분 | statuses에 현재 상태 포함 | 미포함 | 해당 없음 |
| 소득 | 사용자 구간 상한 ≤ 기준 | 사용자 구간 하한 ≥ 기준 | 구간이 기준에 걸침, 또는 "잘 모르겠어요" |
| 추가 항목 | 답변이 필요한 값과 같음 | 다름 | 아직 묻지 않았거나 건너뜀 |

- income_max_pct가 비어 있으면 소득 조건은 판정표에 표시하지 않는다
- 각 규칙 조건에는 raw_text 중 해당 문장을 발췌로 연결 (스프레드시트 "조건별 근거 문장" 열)

### 후보 선정과 정렬
- 후보: 관심 분야가 하나 이상 겹치고, 데이터 상태가 마감이 아닌 정책
- 기본 표시: likely와 check 중 정렬 상위 5개 / 접힌 영역: unlikely 상위 3개
- likely와 check가 0개면 결과 없음 흐름
- 정렬: 상태(likely→check→unlikely) → 마감 임박 먼저 → 마감일 빠른 순(상시는 뒤, 접수 예정 그 뒤) → 관심 분야 일치 수 → id 순

### D-day와 데이터 상태

| 경우 | 배지 | 데이터 상태 |
| --- | --- | --- |
| 마감일이 오늘 | 오늘 마감 | 검수 완료 |
| 마감까지 1~7일 | 마감 임박 D-n | 검수 완료 |
| 8일 이상 | D-n | 검수 완료 |
| 마감일 없음 | 상시 접수 | 검수 완료 |
| 시작일이 오늘 이후 | 접수 예정 (M.D 시작) | 접수 예정 |
| 마감일 지남 | 표시 안 함 | 마감 |
| 확인일로부터 14일 초과 | 기존 배지 + "재확인 필요" | 재확인 필요 |

### 대표 프로필 (정답셋은 AI A·B에 비공개)

| 번호 | 프로필 | 확인하려는 것 |
| --- | --- | --- |
| P1 | 만 23세, 서울, 재학, 취업·생활비, 소득 모름 | 데모 기본. check와 조건부 문장 |
| P2 | 만 22세, 서울 자치구 선택, 휴학, 주거·생활비, 소득 50~100%, 월세 | 주거 추가 항목, likely |
| P3 | 만 24세, 서울, 졸업예정, 취업·훈련, 소득 100~150% | 신분 변화, 마감 임박 정렬 |
| P4 | 만 23세, 서울, 재학, 생활비, 소득 150% 초과 | 소득 미충족 → unlikely와 대안 |
| P5 | 만 21세, 서울 외, 재학, 전체 | 서울 정책 unlikely, 결과 없음 또는 전국 정책만 |

채점: 추천 정확도 = 프로필별 상위 3개 중 정답 정책 수 합계 ÷ 15. 판정 일치율 = 기대 상태와 실제 상태 일치 수 ÷ 전체.

## 5장 AI A · 대화 (요약)

### 메시지 해석 결과 항목
의도(정책 찾기 / 특정 정책 질문 / 비교 요청 / 결과만 보기 / 범위 밖 / 잡담), 프로필 변경(항목·값·시점), 추가 항목 답변, 관심 분야 추가·제외, 언급된 정책 id

해석 기준:
- 확실히 말한 것만 반영. 추측으로 채우지 않는다
- 미래 계획은 시점 "예정"으로 두고 프로필은 바꾸지 않는다
- 폼 값과 다르게 말하면 대화 값을 따른다
- 숫자 소득은 구간으로 바꾸지 않는다

### 후속 질문 선택 기준 (순서대로)
1. 백엔드A가 준 미확인 항목 목록 수집 (이미 물었거나 건너뛴 항목 제외)
2. 항목마다 답에 따라 상태가 바뀔 수 있는 표시 중 정책 수를 센다
3. 수가 가장 많은 항목
4. 같으면 더 위에 있는 정책에 영향 주는 항목
5. 그래도 같으면 1-2 표의 순서

### 답변 구성
요약 한 문장 → 정책별 설명(최대 5개, 정책당 1~2문장) → 조건 안내 → 마감 강조 → 고정 문구("최종 신청 전 공식 공고에서 다시 확인하세요")

- 해요체, 과장·감탄·이모지 없음, 전체 600자 이내
- 판정·조건·금액·날짜가 들어간 문장에는 반드시 각주
- 각주는 AI B와 백엔드A가 넘긴 조건 결과의 발췌에만 연결. 새 발췌를 만들지 않는다
- 금지 표현: 대상입니다, 받을 수 있어요, 확실히, 무조건, 100%, 보장, 걱정 마세요
