# 프로젝트 기본 맥락 (자동 적용)

> 이 파일은 저장소를 클론한 모든 팀원의 Kiro에 자동으로 적용된다.
> 팀 소다쿠키 · 2026 국민대 캠퍼스타운 키로톤 02팀.

## 무엇을 만드는가

서울 거주 만 19~24세 대학생·취업준비생이 기본 정보를 입력하고 자기 상황을 말하면, AI가 공식 공고를
근거로 받을 수 있는 지원제도를 바로 보여주고, 판정에 필요한 것만 되물으며, 신청까지 해야 할 일을
정리해 주는 대화형 서비스. "청년 지원제도를 위한 Perplexity."

## 절대 깨지 않는 P0 세 가지

1. **원문 각주** — 판정 문장에는 반드시 공고 원문 발췌 각주가 붙는다. 각주 없는 판정 문장은 출력하지 않는다.
2. **판정을 바꾸는 후속 질문** — 상위 후보의 판정 상태를 바꾸는 정보만 묻는다. 없으면 묻지 않는다.
3. **즉시 1차 결과** — 폼 제출 직후 규칙 엔진 결과로 카드를 먼저 띄운다. AI 설명은 그 뒤에 스트리밍.

기능을 줄여야 할 때도 이 세 개는 남긴다. 빼는 순서는 `docs/00-overview.md`에 있다.

## 폴더 소유권

| 경로 | 소유 |
| --- | --- |
| `docs/`, `server/` | 백엔드B |
| `frontend/` | 프론트 |
| `data/`, `rules/` | 백엔드A |
| `ai/conversation/` | AI A |
| `ai/judgment/` | AI B |

**자기 역할 폴더 밖의 파일은 수정하지 않는다.** 수정이 필요하면 멈추고 사용자에게 알린다.

## 어긋났을 때 무엇이 이기는가

| 충돌 | 기준 |
| --- | --- |
| 규칙 조건 vs AI 조건 (같은 내용) | 규칙 조건 |
| 폼 값 vs 대화 값 | 대화 값 |
| AI 요약 vs 공고 원문 | 원문 |
| 문서 vs 코드 | 문서. 문서를 먼저 고치고 구현한다 |
| 판정 상태를 AI가 다르게 말함 | 코드가 확정한다. AI는 설명만 |

## 고정 값 (문자 그대로 쓴다)

| 종류 | 값 |
| --- | --- |
| 판정 상태 | `likely`, `check`, `unlikely` |
| 조건 결과 | `met`, `unmet`, `unknown` |
| 판정 주체 | `rule`, `ai` |
| 데이터 상태 | `verified`, `recheck`, `closed`, `upcoming` |
| 의도 | `find_policy`, `policy_question`, `compare`, `result_only`, `out_of_scope`, `smalltalk` |
| 진행 단계 | `searching`, `checking`, `summarizing` |

프로필 항목의 허용 값은 `docs/01-glossary-profile.md` 2~3장이 유일한 기준이다.
새 프로필 항목을 만들지 않는다. 필요하면 멈추고 물어본다.

## 이름 컨벤션

- 서버가 주고받는 본문과 정책 데이터 필드는 snake_case. 각 언어 안에서는 그 언어 관습을 따르고 경계에서만 변환한다.
- 날짜는 `YYYY-MM-DD` 문자열. 시간은 넣지 않는다. 모든 계산은 한국 시간 기준.
- **D-day와 날짜 계산은 코드만 한다. LLM에게 날짜를 계산시키지 않는다.**
- 정책 번호는 `SEOUL-001`, `GOV-007` 형식.
- 파일·폴더 이름은 영어 소문자와 하이픈. 한글 파일명을 쓰지 않는다.

## 전원 금지 사항

- 공고에 없는 금액·날짜·조건을 화면에 보여주지 않는다. 금액과 날짜는 데이터 필드에서만 가져온다.
- 확정 표현 금지: 대상입니다, 받을 수 있어요, 확실히, 무조건, 100%, 보장, 걱정 마세요
- 이름, 연락처, 주민등록번호, 계좌번호를 받거나 저장하지 않는다.
- 세션은 서버 메모리에만 둔다. 데이터베이스를 쓰지 않는다.
- 사용자 메시지 원문과 프로필을 로그에 남기지 않는다.
- 정답셋(`data/eval/`)을 읽거나 참조하지 않는다. AI 담당은 정답을 보지 않고 구현한다.
- 임베딩과 벡터 검색을 쓰지 않는다. 규칙 필터로 좁히고 공고 원문을 그대로 컨텍스트에 넣는다.

## 기술 스택

| 영역 | 결정 |
| --- | --- |
| `server/`, `rules/`, `ai/conversation/`, `ai/judgment/` | **Python** |
| `frontend/` | 미확정. 정적 내보내기가 되는 것 (S3 정적 호스팅) |
| 데이터 저장소 | 없음. 세션은 서버 메모리에만 |

- 서버·규칙 엔진·AI 모듈은 같은 파이썬 애플리케이션 안에서 함수 호출로 연결한다. 별도 서비스로 쪼개지 않는다.
- 파이썬 관습이 snake_case라 서버·규칙·AI 사이에는 이름 변환이 없다. 문서에 적힌 이름을 그대로 쓴다.
- 변환이 필요한 곳은 프론트 경계 한 곳뿐이다.
- 같은 언어라 경계가 흐려지기 쉽다. **규칙 판정 로직을 서버 쪽에 복사하지 않는다.** 판정은 `rules/`에만 있다.
- 파이썬 파일과 모듈 이름은 소문자와 밑줄. 가상환경은 저장소에 올리지 않는다.
- 의존성은 최소로, 버전은 정확히 고정한다. 낯선 패키지 이름은 실제 존재를 확인한다.

## AI 모델

캠프에서 Claude 또는 GPT를 제공한다. 어느 쪽을 쓸지는 백엔드B가 10:30까지 정한다.
모델을 부르는 지점은 메시지 해석·예외 조건 판정·답변 작성 세 곳뿐이다.
호출부를 한 군데로 모아 모델을 바꿔도 깨지지 않게 한다.

## 배포 전제

프론트는 캠프에서 제공하는 **S3에 정적 파일로** 올라간다. 서버는 별도 주소에 올라간다.

- 프론트는 서버 사이드 렌더링을 쓰지 않는다. 단일 페이지 앱으로 만든다.
- 화면 전환을 주소 경로로 나누지 않는다. 온보딩 → 홈 → 대화는 한 화면 안의 상태로 다룬다.
- API 주소는 빌드에 박지 않고 설정 파일로 분리해 실행 중에 읽는다.
- API는 프론트와 다른 오리진이다. 서버가 프론트 주소를 허용 오리진으로 등록해야 한다. 스트리밍도 같은 규칙을 받는다.
- 프론트와 API의 프로토콜을 맞춘다. 어긋나면 브라우저가 요청을 차단한다.

## 커밋

형식은 `타입(범위): 한 줄 요약`. 타입은 `feat`, `fix`, `docs`, `refactor`, `chore`, `data`.
범위는 폴더 이름. 요약은 한국어 현재형, 50자 이내, 마침표 없이.
전체 추가 대신 파일을 지정해서 스테이징한다. `.env`, 정답셋, 설문 원본은 커밋하지 않는다.
